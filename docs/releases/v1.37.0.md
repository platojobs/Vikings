# v1.37.0 · 设备影子变更历史与按版本精确回滚

> 发布日期：2026-11-13
> 定位：让每一次期望状态真实变化都有完整、不可变快照可核查，
> 并可用一次操作精确恢复旧配置，同时保留设备实际上报与后续主动同步语义。

## 版本定位

- **完整不可变历史**：merge、显式清键、批量修改和回滚在实际改变 `desired` 后保存完整快照。
- **精确回滚**：按目标版本完整替换当前期望，目标没有的当前键会删除；不是对旧快照再做 merge。
- **只追加、不改写**：回滚生成新版本和 `rollback` 历史，目标版本与既有快照保持不变。
- **同内容幂等**：当前期望已与目标一致时不空增版本、不重复写历史或审计。
- **不伪造设备已应用**：回滚不修改 `reported` / `reported_version`，由设备后续 REST 主动上报确认。
- **全端可见、写权限收口**：Web 支持历史与二次确认回滚；移动端只读、按需分页查看历史。

## 数据模型

### `device_shadow_revision`（新表，迁移 `0012_shadow_history`）

| 字段 | 说明 |
| --- | --- |
| `id` | 快照 ID |
| `device_id` / `version` | 设备与期望版本；数据库唯一约束防止同设备版本重复 |
| `desired` | 该版本变更后的完整期望快照，不随当前影子继续变化 |
| `changed_keys` | 相对前一状态新增、删除或值变化的键，排序后保存 |
| `action` | `baseline / merge / clear / batch / rollback` |
| `source_version` | 回滚目标版本；非 rollback 为 `NULL` |
| `created_at` / `created_by` | 快照时间与操作人 |

历史只保存期望快照，不复制 reported。删除设备时由服务显式清理当前影子及其历史。

## 历史与回滚语义

1. 每次期望真实变化后记录变更后的完整 `desired`，同值 merge、删除不存在的键等幂等操作不写新快照。
2. `baseline` 表示升级或首次写入时可确认的当前状态；`merge / clear / batch` 对应既有写入口。
3. 回滚读取目标完整快照并替换当前 `desired`，因此旧快照没有的后续新增键也会被移除。
4. 回滚成功时当前 `version +1`，新历史 `action=rollback`、`source_version=目标版本`，
   `changed_keys` 同时覆盖新增、删除和值变化。
5. 当前期望与目标一致时返回当前影子，不产生无意义版本；目标快照不存在返回 404。
6. 回滚只改变云端期望。设备下一次唤醒仍需 GET 当前影子、实际应用后 POST reported；
   被完整快照移除的旧配置键必须在 reported merge patch 中显式上报 `null`。

## 接口与权限

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/devices/{id}/shadow/history` | 登录可读 | 按版本倒序分页；`limit` 默认 50、范围 1~100，`offset` 默认 0 |
| POST | `/api/devices/{id}/shadow/rollback` | operator/admin | 入参 `{"version":N}`，完整替换回滚并返回当前 `DeviceShadowOut` |

历史响应包含 `items / total / limit / offset`；每条快照包含版本、完整 `desired`、动作、
变化键、来源版本、时间与操作人。未登录 401，viewer 回滚 403，设备或目标快照不存在 404。

新增审计动作 `device.shadow_rollback`，只记录来源版本、新版本、变化键与 changed，
不记录期望状态值；历史表按功能需要保存完整快照。

## 全端能力

- **Web**：设备详情按需加载历史，每页 20 条，可继续加载更早版本；展示版本、动作、当前标记、
  操作人、时间、来源版本、变化键和完整 JSON。operator/admin 二次确认后回滚，
  成功或幂等结果均同步当前影子、编辑器与已展开历史。
- **移动端**：设备详情首屏不请求历史；展开后每页 20 条只读加载，展示同一套快照与变化键。
  不提供期望编辑或回滚入口，写操作仍集中在 Web。
- **模拟器**：完整快照回滚删除配置键时，计算旧 `reported_state` 与新 `desired` 的键差，
  对缺失键显式上报 `null`，保证 reported 能精确收敛而不是残留旧值。
- **移动端版本**：`device_app/pubspec.yaml` 同步为 `1.37.0+36`，构建号大于上一标签中的 34。

## 升级与兼容性

- 只新增历史表和两个端点；既有 `DeviceShadowOut`、desired/reported merge、同步状态机、
  批量目标口径及 MQTT Topic/报文均未改变。
- `0012_shadow_history` 升级时为 v1.36.0 每台当前影子回填一条 `baseline`，
  使用当前版本、完整 desired 和可确认的操作人/时间；不会臆造升级前未保存的更早历史。
- downgrade 只删除 `device_shadow_revision`，不回退或删除 `device_shadow` 当前状态。
- 旧客户端不调用新端点即可保持原行为；新移动端历史视图依赖 v1.37.0 网关。

## 已知边界

- 设备影子仍是**唤醒后的 REST 主动拉取/上报**；本版本未新增 shadow MQTT Topic，
  离线设备只能在下次上线时消费回滚后的期望。
- 历史从本版本开始累积；升级前只有当前状态基线，无法恢复从未保存的旧版本。
- 移动端历史只读；批量期望、单台编辑与回滚仍只在 Web 提供。
- 模拟器与 E2E 不证明真实硬件已写入配置。真实硬件必须实际应用成功后，再上报完整状态与版本。
