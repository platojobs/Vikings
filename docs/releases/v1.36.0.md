# v1.36.0 · 设备影子：期望 / 上报 / 同步状态机与批量下发

> 发布日期：2026-11-13
> 定位：把设备配置从一次性指令扩展为可持续核对的「期望状态 vs 实际上报」，
> 串联设备标签筛选、批量操作逐台结果，以及设备上线后的主动同步。

## 版本定位

- **一行一设备的影子**：新增 `device_shadow`，保存 `desired`、`reported`、期望版本与设备已应用版本。
- **服务端唯一状态机**：统一返回 `empty / synced / pending / offline_pending`、`diff_keys`
  与 `pending_desired`；Web 和移动端只展示，不各自推导另一套状态。
- **幂等变更**：merge patch 真正改变期望才递增版本；`null` 清键；乱序上报不会让已应用版本后退。
- **批量沿用既有目标口径**：复用设备列表的分组、标签与跨页选择，逐台返回真实结果并写聚合审计。
- **上线主动同步**：模拟器每次唤醒拉取期望、模拟应用后上报实际状态与版本；离线期望无需重复下发。

## 数据模型

### `device_shadow`（新表，迁移 `0011_device_shadow`）

| 字段 | 说明 |
| --- | --- |
| `device_id` | 主键，一行一设备；删除设备时显式清理，避免孤儿影子 |
| `desired` / `reported` | PostgreSQL JSONB / SQLite JSON 的扁平键值对象 |
| `version` | 期望版本，仅实际变更时 +1 |
| `reported_version` | 设备已应用版本，只前进并夹紧到当前 `version` |
| `desired_updated_at` / `desired_updated_by` | 最近实际期望变更时间与操作人 |
| `reported_updated_at` | 最近实际上报时间 |
| `created_at` / `updated_at` | 行时间戳 |

`sync_status` 与差异不冗余落库，而是由两份状态和设备在线状态实时计算，避免在线事件与影子双写漂移。

## 语义

1. **期望 merge patch**：`{"report_interval":30,"led":null}` 表示修改上报周期并删除 `led` 期望；
   同值覆盖、删除不存在的键都不递增版本。
2. **实际状态 merge**：设备可只上报变化字段；`null` 清除对应上报键。
3. **差异只针对期望键**：`reported` 额外拥有的自由状态键不算差异；`desired={}` 时状态为 `empty`。
4. **版本不是唯一判据**：`reported_version` 用来识别设备消费进度，最终 `synced` 仍要求字段值一致。
5. **在线状态参与解释**：有差异时在线为 `pending`，离线为 `offline_pending`；设备下一次上线后主动同步。
6. **载荷边界**：单次最多 32 键，键长 1~32；值仅字符串、数字、布尔、null，禁止数组与嵌套对象。

## 接口与权限

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/devices/{id}/shadow` | 登录可读 | 期望、上报、版本、差异与同步状态 |
| PUT | `/api/devices/{id}/shadow/desired` | operator/admin | merge 写期望，null 清键 |
| DELETE | `/api/devices/{id}/shadow/desired?keys=a&keys=b` | operator/admin | 显式清除期望键 |
| POST | `/api/devices/{id}/shadow/reported` | operator/admin | merge 上报实际状态与已应用版本 |
| POST | `/api/devices/shadow/desired/batch` | operator/admin | 按 ID/标签/分组交集批量写期望 |

- 未登录 401，viewer 写入 403，设备不存在 404；非法 patch 返回 400/422 与可读原因。
- 批量最多 200 台，逐台状态为 `updated / unchanged / not_found`，并返回
  `matched / updated / unchanged / not_found` 汇总。
- 同时提供显式 ID、标签和分组时取交集；被筛选排除的现存设备不进入批次，也不会误报为不存在。
- 审计动作：`device.shadow_desired_update`、`device.shadow_desired_batch`；只记录键名、版本、
  筛选和数量，不记录期望状态值。

## 全端能力

- **Web**：设备详情提供期望 / 上报 / 待同步差异三栏、同步徽章、版本、刷新、merge patch
  编辑与单键清除；设备列表新增「批量期望」，复用跨页选择与标签/分组筛选并展示逐台结果。
- **移动端**：设备详情并发加载影子，提供状态徽章、双版本、期望/上报值和差异高亮的只读视图；
  viewer 与写角色看到同一数据源，编辑集中在 Web。
- **模拟器**：配置 `GATEWAY_API_URL` 与 `GATEWAY_API_TOKEN` 后，每轮上线执行 GET → 应用 → POST；
  已同步不重复上报，REST 失败不阻断原有 MQTT 传感器与 OTA 行为。未配置时保持旧行为。

## 兼容性

- 只新增影子表与影子端点；既有设备、标签、指令、OTA、告警和 MQTT Topic/报文均未改变。
- 旧客户端不调用影子端点即可保持原行为；新移动端依赖 v1.36.0 网关提供详情影子数据。
- `0011_device_shadow` 可直接在既有库升级；downgrade 会删除 `device_shadow` 及其数据，
  不影响既有设备、指令与 OTA 表。回滚前如需保留影子应先备份。

## 已知边界

- 当前设备侧同步是**唤醒后的 REST 主动拉取/上报**，未新增 shadow MQTT Topic，也没有网关实时推送；
  离线设备只能在下次上线时消费期望。
- POST reported 使用 operator/admin 用户 access token；模拟器仅用于联调，不能据此宣称已具备
  设备级 MQTT 影子鉴权。生产硬件的 MQTT 影子链路需后续独立设计与验收。
- 模拟器只模拟配置应用与回执，不证明真实硬件已写入配置；真实设备必须在应用成功后再上报版本。
- 移动端只读，不提供批量或单台期望编辑；Web 是本期唯一期望管理入口。
