# v1.14.0 发布说明

- 发布日期：2026-11-04
- 提交：本提交（附注标签 `v1.14.0` 指向该提交）
- 标签：`v1.14.0`

## 版本定位

一句话：把「后台改设备分组」变成一条实时事件，移动看板无需等待轮询即可就地更新分组名、
移出不再匹配的筛选结果，并让分组 chips 与 `total` / 汇总卡重新对齐服务端口径。

本轮不新增产品概念、不新增端点、不新开 MQTT 通道：复用既有 `MqttGatewayClient.publish`
与 `device/system/*` 系统级 Topic 命名，事件作为可选能力向后兼容 v1.13.x。

## 只读核对结论

| 项 | 现状 | 本轮结论 |
| --- | --- | --- |
| 改分组入口 | Web 设备管理页走 `PATCH /api/devices/{deviceId}`；后台只有批量**注册**，没有批量改分组 | 只在该 PATCH 路径接入事件，不新增批量接口 |
| 网关发布通道 | `MqttGatewayClient.publish(topic, payload, qos)`，已有 `device/system/alert` 先例 | 新增同构 Topic `device/system/group`，QoS1、不 retain |
| 移动端实时解析 | `RealtimeParser` 按 Topic 分派，未知 Topic 返回 null | 新增 `GroupChangedEvent`；旧客户端遇未知 Topic 行为不变 |
| 分组 chips | `GET /api/devices/groups`（空分组并入「未分组」） | 事件后重拉该接口，不用本地增减维护 chips |
| 订阅范围 | `RealtimeTransport` 订阅固定的 `device/+/...` 与 `device/system/alert` | 增加 `device/system/group`，仍是同一 WS 通道 |

## 行为变化

1. **事件发布**：`PATCH /api/devices/{deviceId}` 落库**提交之后**，若 `group_name` 真正变化，
   网关发布 `device/system/group`，报文见 `docs/contracts.md` 2.6：
   `deviceId` / `groupName` / `previousGroupName` / `operator` / `ts`。
2. **边界**：设备不存在返回 404 且不发布；只改名称、重复提交同一分组不发布；
   MQTT 不可用时只记告警，PATCH 仍返回 200（与 v1.13.x 编辑语义一致）。
3. **移动看板**：
   - 收到事件立即就地更新已加载设备的 `group_name`；
   - 当前筛选为某分组且设备已不属于该组时立即移出列表，`total` 同步减一；
   - 250ms 防抖后重拉当前分页、`GET /api/devices/groups` 与 `/api/stats/overview`，
     chips / `total` / 汇总卡统一回到服务端口径（已加载多页时回到第 1 页，与轮询兜底一致）；
   - 实时断开期间靠 15 秒轮询或手动刷新体现，不会「永远看不到」；
   - 改组后新进入当前筛选、但尚未加载的设备不即时插入，下次刷新/翻页出现（与 v1.11.0 策略一致）。

### 取舍说明

- **chips 用「重新拉取」而非本地增量**：分组可能被并发改名，某组也可能因最后一台设备移出而消失；
  本地增减需要复制服务端的归并规则（空分组 → 未分组），容易与 `GET /api/devices/groups` 不一致。
  分组变更是低频操作，多一次 REST 查询换取口径一致更划算。
- **先本地移除、再服务端对账**：立即移除保证筛选结果不出现「已改组却还留在列表里」的错觉；
  随后的对账刷新把 `total` 与分页数据拉回真实值，避免本地减一与服务器实际总数长期偏差。
- **发布放在 commit 之后**：订阅端收到事件后若立刻回查 REST，读到的必定是新分组，避免「事件先到、数据后到」的竞态。

新增回归断言：

- 事件报文五个字段的类型与取值（`ts` 为毫秒整数）；
- 设备不存在 → 无事件；分组未变化 / 仅改名 → 无事件；
- 发布异常 → 返回 False 且不抛出（REST 语义不变）；
- 看板：改组后设备移出当前筛选、`total` 同步，chips 刷新后出现新分组；
- 看板：未筛选时分组的就地更新与 chips 刷新；
- v1.13.x 既有接口与字段未改动，Web 路由守卫 7 条用例保持全绿。

## 兼容性

- MQTT：新增 Topic，旧客户端不订阅即无感知；报文为新增格式，未改动任何既有 Topic。
- REST：`PATCH /api/devices/{deviceId}` 入参、响应字段与错误码均未变化。
- 移动端：未升级的 v1.13.x 客户端继续按原逻辑工作，只是分组变更需要等下一次刷新。

## 已知限制

- 后台没有批量改分组，因此不存在「批量事件」；批量注册只在创建时写分组，不触发变更事件。
- 事件只覆盖已加载设备的分组名；改组后新进入当前筛选的设备仍需下次刷新/翻页补齐。
- 对账刷新会把已加载的后续页收起为第 1 页，与既有轮询兜底行为一致。
- `operator` 仅用于排障，移动看板不展示操作人。

4. `gh` 创建 GitHub Release `v1.14.0`。

## 升级建议

- 网关与移动端一起升级即可获得实时分组同步；只升级网关不影响旧客户端。
- 若在网关侧新增其他影响设备属性的写接口，建议复用 `update_device_with_group_event`
  的「提交后发布 + 失败降级」模式，并同步补充 `docs/contracts.md` 与 E2E。
