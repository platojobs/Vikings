# v1.22.0 · P1-5 移动端可发布产物与依赖治理

> 发布日期：2026-11-05
> 需求：P1-5（release 签名、CI 制品、构建号策略、Dependabot、Actions 升级）

## 版本定位

v1.22.0 把移动端从「只能本地 debug 运行」推进到「可重复产出、可验签的构建制品」：

1. release 构建支持 keystore 注入（环境变量 / `key.properties`），
   缺密钥时**显式降级**为 debug 签名并在日志、产物名、`SIGNING.txt` 中标明；
2. 明确 `versionName` / `versionCode` 与 pubspec `1.x.y+build` 的对应关系，
   标签构建校验版本一致性与 build 递增；
3. CI 新增发布作业，只在 `main` 推送与 `v*` 标签构建 APK/AAB 并上传 artifact；
4. 启用 Dependabot（pub / pip / npm / github-actions），按周分组更新；
5. 全部 Actions 升级到 Node 24 运行时版本，消除 Node.js 20 弃用提示。

## 签名策略：明确降级 + 严格模式

没有采用「缺密钥直接失败」作为默认行为，原因：仓库无法自行生成真实发布密钥，
强制失败会让未配置 secrets 的 `main` CI 长期红灯。最终策略：

| 场景 | 行为 |
| --- | --- |
| 有环境变量或 `key.properties` | 生成 `signingConfigs.release`，正常签名 |
| 无签名材料（默认） | 回落 debug 签名；Gradle 打印 WARNING；CI 产物名带 `-debug-signed`；`SIGNING.txt` 写明不可分发 |
| 无签名材料 + `REQUIRE_SIGNED_RELEASE=true` | 构建直接失败，输出缺失的环境变量/文件清单 |

关键约束：**绝不静默使用 debug 密钥冒充发布包**。verification 中用临时测试
keystore 证明签名链路可用，用无密钥构建证明降级行为符合上述表。

## 构建号策略

- `pubspec.yaml` 的 `version: 1.x.y+build` 是唯一来源：
  `versionName=1.x.y`，`versionCode=build`。
- 正式发布：手动改 pubspec，CI 在标签构建时校验
  1) `vX.Y.Z` 与版本名一致；
  2) build 大于最近一个 `v*` 标签的 build。
- main 快照：`versionName=1.x.y-snapshot.<sha7>`，
  `versionCode=GITHUB_RUN_NUMBER + 100000`，保证同一通道递增且不重号。
- 快照版 versionCode 高于正式版，从快照切回正式需先卸载（文档已写明）。

## CI 触发条件与制品

- 触发：`push` 到 `main`、`push` 标签 `v*`；**PR 不构建**（避免大文件与额外耗时）。
- 产物：APK + AAB + `SHA256SUMS` + `SIGNING.txt`，
  artifact 名 `iot-device-app-<versionName>-<signed|debug-signed>`，保留 14 天。
- CI 步骤内用 `apksigner verify --print-certs` 与 `aapt2 dump badging` 打印证书 DN 和
  `package:` 行，下载后可用同样命令复核。

## 依赖治理

`.github/dependabot.yml` 覆盖四个生态，统一每周一 09:00（Asia/Shanghai）：

- minor/patch 分组为一个 PR，major 单独；
- 单生态 `open-pull-requests-limit: 5`；
- 未加密钥、未引入阻断式 `npm audit` / `pip-audit` 门禁，理由见
  `docs/mobile-release.md` 第 7 节：避免与本次改动无关的长期红灯；
  漏洞基线由 Dependabot alerts / security updates（仓库设置）承担。

## 安全边界

- keystore、口令、`key.properties` 一律不入库（`.gitignore` 已覆盖）；
- 文档与示例口令均为占位符；
- Gradle/CI 日志只打印签名来源与证书 DN，不打印口令；
- CI 解码的 keystore 写入 `$RUNNER_TEMP`（600 权限），runner 结束即销毁；
- 本次验证使用的临时 keystore 位于 `/tmp`，验证后删除，不进入仓库。

## 偏差与遗留

- 仓库未配置真实发布 secrets，因此 CI 实际产物为 `-debug-signed`；
  正式签名链路由本机临时 keystore 验证，配置 secrets 后即可产出 `-signed`。
- 未加入阻断式依赖漏洞门禁，需仓库管理员开启 Dependabot alerts。
- iOS 出包（证书/描述文件）不在本次范围。
