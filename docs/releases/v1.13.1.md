# v1.13.1 发布说明

- 发布日期：2026-11-04
- 提交：本提交（附注标签 `v1.13.1` 指向该提交）
- 标签：`v1.13.1`

## 版本定位

一句话：为 Web 后台补上最小可用的单元测试基建，用 7 条路由守卫用例锁住登录态与权限行为，并接入 CI 的 `web` 作业。

本轮不新增产品功能，也不改动任何页面表现：只把既有守卫逻辑抽成可注入 history 的 router 工厂，
让测试直接驱动生产 router 并断言真实导航结果。

## 选型依据（只读核对后的结论）

| 项 | 现状 | 结论 |
| --- | --- | --- |
| Vue / 路由 | `vue@3.5.44`、`vue-router@4.6.4` | 直接用 vue-router 的 `createMemoryHistory` 隔离用例 |
| 构建 | Vite 6.4.5，`vite.config.ts` 已含 `@` 别名、自动导入与 Element Plus 按需引入 | 测试配置用 `mergeConfig` 复用生产配置，不另起一套解析规则 |
| 既有测试框架 | 无（`package.json` 无 vitest / jest / test-utils） | 新增 `vitest@3.2.7` + `jsdom@25.0.1`，未引入 `@vue/test-utils`（本轮只断言路由状态，不需要挂载组件） |
| 登录态与权限 | `utils/auth.ts`（localStorage token/user）、`utils/permissions.ts`（`currentRole`） | 测试复用这两个生产模块准备登录态，不 mock 权限判断 |
| CI | `web` 作业原为 `npm ci` + `npm run build` | 在构建前插入 `npm run test`，失败即作业失败 |

## 生产代码改动（最小化）

- `web/src/router/index.ts`：把守卫抽成具名函数 `authGuard(to)`，并新增
  `createAppRouter(history = createWebHistory())` 工厂；默认导出 `router` 保持不变，
  守卫规则、重定向目标与顺序完全未改。
- 测试注入 `createMemoryHistory()`，每个用例拿到独立 router，互不影响导航历史。

## 测试覆盖（7 条，全部断言真实 `currentRoute`）

| 用例 | 断言结果 |
| --- | --- |
| 未登录访问 `/devices?keyword=tower` | `/login`，`redirect=/devices?keyword=tower` |
| 未登录访问 `/` | `/login`，`redirect=/dashboard` |
| 已登录访问 `/login` | 回到 `/dashboard` |
| admin 访问 `/system` | 允许进入，停留 `/system` |
| viewer 访问 `/system` | 被拒并回到 `/dashboard` |
| operator 访问 `/users` | 被拒并回到 `/dashboard` |
| 已登录访问 `/no-such-page/deep` | 落到兜底路由 `/dashboard` |

工程化细节：

- `web/vitest.config.ts`：`environment: 'jsdom'`、`include: ['src/**/*.spec.ts']`、
  `setupFiles: ['./test/setup.ts']`；`server.deps.inline: ['element-plus']` 解决按需引入
  组件自带 CSS 在 Node ESM 下无法加载的问题。
- `web/test/setup.ts`：Node 26 自带实验性 `localStorage` 且未配置 `--localstorage-file`
  时取值为 undefined，补丁用 jsdom 的 Storage 回填；Node 20（CI）环境不会触发。
- `web/package.json`：新增 `"test": "vitest run"`，CI 与本地同一命令。

## 已知限制

- 用例只覆盖路由守卫的导航结果，不挂载页面组件；页面级交互仍依赖构建回归与 E2E。
- 为保持真实路由，导航会真实加载对应懒加载视图；首次运行约 3s，属可接受范围。
- 未引入 `@vue/test-utils`；后续若需要断言页面渲染，再按需补充。
- 本地 Node 26 需要 `test/setup.ts` 的 localStorage 补丁；CI 使用 Node 20，无此现象。

## 升级建议

- 纯测试与工程化改动，运行时行为无变化，按常规升级即可。
- 后续新增路由或调整权限规则时，请同步更新 `router.spec.ts`，让守卫行为持续被覆盖。
