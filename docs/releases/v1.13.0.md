# v1.13.0 发布说明

- 发布日期：2026-11-04
- 提交：本提交（附注标签 `v1.13.0` 指向该提交）
- 标签：`v1.13.0`

## 版本定位

一句话：移动看板设备详情「历史上报」改为分页加载并与实时上报协同；Web 后台按路由与依赖做代码分割，入口主包从 693.24 kB 降到 312.04 kB。

本轮属收口版本，不新增产品概念：移动端只把详情页固定 `limit=10` 改为可翻页，网关补一个可选 `offset`；Web 端不新增页面，只调整懒加载与打包策略。

## 移动看板：设备详情历史上报分页

- **首屏一页**：`GET /api/devices/{id}/records?limit=11&offset=0`，多取的 1 条只用于判断是否还有更早数据，列表展示最新 10 条并改为时间倒序（最新在前）。
- **加载更早**：滚动到页脚或点击「加载更早」，按 `offset=<已从服务端取回条数>` 取下一页追加到列表末尾；实时插入不会改变服务端游标。
- **三态可读**：加载中「加载中…」/「正在加载更早数据…」，取完「没有更早数据」，首页即空「暂无历史上报」。
- **实时协同**：该设备新上报通过 MQTT 实时通道插到列表顶部；用户已向下浏览时按插入行的实际高度补偿滚动偏移，正在看的历史数据不会被顶走；停留在顶部时不做补偿，新数据直接可见。
- **注入方式不变**：`storage` / `apiClientFactory` / `realtimeServiceFactory` 继续可注入，新增逻辑全部可在 Widget 测试中验证。

## 网关接口（最小增量，默认行为不变）

- `GET /api/devices/{device_id}/records` 新增可选 `offset`（默认 `0`，`ge=0`）：按 `ts desc` 跳过 `offset` 条后取 `limit` 条，最终仍翻转为时间正序返回。
- 不传 `offset` 时不生成 OFFSET 子句，响应结构、排序与语义与旧版完全一致；补了「默认与显式 `offset=0` 结果一致」的回归断言。
- 新增「`offset` 逐页向更早取数、越界返回空列表」用例。
- 不新增端点，旧客户端与旧网关互不影响（旧网关忽略 `offset` 时客户端只显示首屏一页）。

## Web 后台代码分割

- **路由全部懒加载**：登录页由静态导入改为 `() => import()`，连同仪表盘、设备、历史、告警、审计、账号、OTA、系统状态全部按需加载，入口只保留外壳与守卫。
- **稳定大依赖单独分包**：`manualChunks` 将 `echarts` / `zrender` 归入 `echarts`，`mqtt` 归入 `mqtt`；Element Plus 继续按需引入，不整包合并。
- **构建产物（实测，无 chunk 体积告警）**：`index` 312.04 kB（原 693.24 kB）、`mqtt` 345.32 kB、`echarts` 482.73 kB、`el-table-column` 89.96 kB、`HistoryView` 110.64 kB，其余业务视图 2.9 ~ 34.3 kB。
- **路由行为不变**：未登录访问受保护路由仍重定向 `/login?redirect=...`；已登录访问 `/login` 回 `/dashboard`；`/users`、`/system` 仍仅 admin 可见。构建后用浏览器实测：守卫重定向、admin 登录进入仪表盘、`/system` 正常加载。

## 已知限制

- 详情页每页固定 10 条；如需调整需同时修改客户端 `_pageSize` 与探测 `limit`。
- 实时插入按插入行高度补偿滚动位置；若未来详情行改为多行可变高度，需要按实际测量值补偿（当前实现已按渲染高度测量，不依赖固定常量）。
- 历史上报分页使用 `offset`，在数据持续高频写入时极端情况下可能出现页边界重复，客户端已按「时间戳 + seq」去重。
- Web 入口仍会同步加载 MQTT 客户端（外壳状态灯需要），`echarts` 与业务视图均不进入首屏请求。

## 升级建议

- 网关与 Web 后台为向后兼容改动，现有调用方无需调整。
- 建议移动端与本版网关配套，以使用详情页「加载更早」；仅升级移动端时功能仍可用（只显示首屏一页）。
