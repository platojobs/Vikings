# v1.10.0 发布说明

- 发布日期：2026-11-04

## 版本定位

一句话：移动看板支持按设备名 / ID 搜索与按状态筛选，网关 `/api/records/latest` 同步提供可选的过滤与分页参数，且完全向后兼容。

本轮以移动端可用性为主，网关只做纯增量：新参数全部可选，不传时行为与 v1.9.3 完全一致。

## 移动看板

- **设备搜索**：顶部搜索框按设备名称或设备 ID 模糊匹配，大小写不敏感；输入采用 300ms 防抖，避免逐字符触发请求。
- **状态筛选**：全部 / 在线 / 离线 / 有告警。「有告警」按未处理告警的设备集合聚合；切换筛选后会重新拉取首屏快照。
- **分页与懒加载**：设备列表每次渲染 20 条，超出部分通过底部「加载更多」增量展示，避免一次性构造全量卡片。
- **空状态**：筛选无结果时展示「没有匹配的设备」并说明当前筛选条件，给出清空关键词 / 切回「全部」的提示。
- **汇总卡**：始终保留全量口径（设备总数 / 在线 / 未处理告警），并标注「筛选结果 N 台 / 全部 M 台」，筛选无结果时不会被清空，避免误解为设备丢失。
- **实时协同**：筛选只作用于渲染层，MQTT 的上报 / 上下线 / 告警事件仍写入完整快照，实时值不会因筛选丢失；上下线事件会即时改变「在线 / 离线」筛选结果。

## 网关接口

- `GET /api/records/latest` 新增可选参数：
  - `status`：`online` / `offline`，按设备状态过滤；
  - `keyword`：最长 64 字符，同时匹配设备 ID 与名称；
  - `limit`：1~500，可选；`offset`：≥0，默认 0。
  - **不传任何参数时**返回结构与语义与历史一致：每个设备各自最新一条、按时间倒序、不截断，老客户端无需改动。
- `GET /api/devices` 既有的 `status` / `keyword` / `group` / `page` / `pageSize` 参数未做任何语义变更，本轮仅补充过滤、分页与「不传参数行为不变」的回归测试。

## 已知限制

- 移动看板首屏设备快照上限为 100 台，超过后本地筛选不覆盖全量；网关已具备 `page/pageSize/status/keyword` 服务端分页，规模上来后可平滑切换。
- 「有告警」筛选基于未处理告警列表（`pageSize=50`），未处理告警超过 50 条时筛选结果可能不完整。
- web 构建主包仍大于 500kB、CI 仍有 Node 20 弃用提示，均为既有问题，本轮未引入。
