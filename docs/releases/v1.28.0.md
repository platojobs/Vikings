# v1.28.0 · 设备批量操作（批量指令 + 批量 OTA）

> 发布日期：2026-11-05
> 定位：补齐「能批量注册 200 台、升级却只能一台台点」的运维不对称。

## 版本定位

- **批量指令走真正的服务端批量端点**：新增 `POST /api/devices/commands/bulk`，
  不是前端循环 N 次单设备接口。服务端串行预检 + 下发，一次请求返回逐台结果。
- **批量 OTA 复用既有任务端点**：不重造流程，仍由 `/api/ota/tasks` 创建任务；
  任务级汇总与逐台状态沿用 v1.23.0 的终态守卫与超时巡检。
- **提交前暴露风险**：离线、未签发/已吊销凭证的设备在确认对话框里提前列出，
  不再等任务超时后才发现。
- **规模对齐**：批量注册、批量指令、批量 OTA 单次上限统一为 **200 台**。

## 能力与真实边界

### 批量指令

| 项 | 边界 |
| --- | --- |
| 端点 | `POST /api/devices/commands/bulk` |
| 类型 | `calibrate` / `config` / `reboot`；**`ota` 返回 422**，升级走独立任务流程 |
| 上限 | 200 台，重复 ID 服务端去重 |
| 权限 | operator / admin 可调用，viewer 403 |
| 部分失败 | 单台发布失败不中断整批，逐台返回 `failed` 原因 |
| 跳过 | 设备不存在、设备离线（离线且无凭证元数据时补充说明） |
| 幂等 | 可选 `request_id`：同一操作人 10 分钟内重放返回首次结果，不重复下发 |
| 审计 | 每个非重放批次一条 `command.bulk_create`（含计数与抽样原因），不写 N 条 |

**哪些类型在批量场景禁用**：`ota` 被端点 schema 拒绝。理由：OTA 需要任务级
`total/success/failed` 汇总、分片进度与失败隔离，退化成普通指令会丢失这些语义。

**为什么不复用单设备端点**：前端循环会制造 N 个并发请求、部分失败只能靠客户端拼装、
幂等与审计散落成 N 条；服务端批量端点能统一预检、串行下发、一次审计并返回稳定分类。

### 批量 OTA

- 复用 `POST /api/ota/tasks`，`deviceIds` 上限从无上限收紧为 200（与注册一致）。
- 设备列表勾选后「批量 OTA」跳转 OTA 页并带入预选；也可在 OTA 页直接多选。
- 提交前预检：离线、未签发/已吊销凭证的设备台数 + 前 3 个 deviceId 直接展示。
- 二次确认写清目标台数、失败风险与「任务下发后不能撤回」。
- 任务卡片展示 `成功 / 失败 / 待回执 / 共`，展开可见逐台 `state / progress / message`。
- **与 v1.23.0 终态守卫的关系**：任务仍按设备独立统计终态；单台失败只计该台 `failed`，
  其他设备照常推进；`success + failed == total` 后不再接受迟到回执。

## 规模与体验

- 多选支持跨页保留（`row-key` + `reserve-selection`），上限 200；超出时取消当次勾选并提示。
- 提交是**一次请求**而非 200 次并发，服务端串行下发；按钮进入 loading 状态，
  结果返回后按成功/失败/跳过分组展示，避免长时间「假死」。
- 设备列表性能不变：表格仍是服务端分页（默认 20 条/页），勾选状态仅存 deviceId + 行快照。

## 结果呈现

批量指令结果弹窗分三组，每台设备一条记录：

- **成功**：`device_id` + `cmd_id`；
- **失败**：`device_id` + 具体原因（Broker 断开等）；
- **跳过**：`device_id` + 具体原因（不存在 / 离线 / 未签发有效凭证）。

重放请求会明确标注「本次为重复提交，已返回首次结果（未重复下发）」。

## 兼容与升级

- 无数据库迁移；批量端点为新增路径，既有单设备指令端点行为不变。
- `/api/ota/tasks` 仅新增上限校验（>200 返回 422）；历史任务读取不受影响。
- 移动端仅 `pubspec.yaml` 同步 `1.28.0+27`，无代码变更。
- 幂等窗口存储在网关进程内，适用于当前单进程部署；多副本部署需迁移到共享存储
  （已在 `docs/contracts.md` 3.7.1 标注）。

## 明确未覆盖

- 批量指令的失败路径只覆盖「下线发布失败」；设备级拒绝/回执失败仍通过单设备指令历史查看，
  批量结果不等待回执（避免一次请求长时间挂起）。
- OTA 批量的「跳过」只发生在 Web 预检与人工确认，服务端仍会为所选设备建任务
  （离线设备最终由超时巡检置 failed）；这是既有任务语义，本版不改变。
- 真机操作（跨页勾选、200 台量级提交体验）需在真实环境按
  `docs/operations.md` 第 12 节执行。
