# v1.32.0 · 电池健康与续航看板

> 发布日期：2026-11-05
> 定位：电池供电设备真正先坏在电上。除了「电压低到阈值才告警」，运维还需要提前知道
> 哪些设备会在下一次巡检前掉电、哪些产线整体电量在加速下滑。

## 版本定位

- **只补真实缺口，不重复批量能力**：v1.28.0 已有批量指令/批量 OTA，v1.29–v1.31 已覆盖通知与导出；
  本次新增的是跨设备的**电量风险分层与衰减趋势**，三端此前只有单设备详情与阈值告警。
- **一个口径，不在前端分摊计算**：聚合、分层、排序全部在网关完成，Web 只负责展示；
  阈值随响应返回，前端不硬编码。
- **只认真实上报**：窗口内无任何 `sensor_record` 的设备记 `unknown`，不插值、不补假值；
  离线设备若窗口内有记录仍参与计算，避免「没上报就当 100%」。
- **衰减用最小二乘而不是首尾相减**：先按 UTC 自然日求每日平均电量，再拟合斜率，
  降低单条异常值的影响；稳定/充电（斜率 ≤ 0）不输出预计天数，也不进风险清单。
- **只读、无迁移、无状态机变更**：viewer / operator / admin 均可查看，不写审计；
  不新增表、不改变任何指令/OTA/告警状态机。

## 判定口径

| 维度 | 规则 |
| --- | --- |
| 最新值 | 窗口内该设备最后一条记录的 `battery` / `voltage` / `ts` |
| 衰减 `drain_per_day` | 每日平均电量对天做最小二乘，取反得到百分点/天；< 0.01 视为稳定 → `null` |
| 预计天数 `days_to_critical` | `(最新电量 - 15) / drain_per_day`；电量 ≤ 15% 时为 0；无法估算为 `null` |
| `critical` | 电量 ≤ 15% **或** 预计 ≤ 7 天 |
| `warning` | 电量 ≤ 30% **或** 预计 ≤ 30 天 |
| `unknown` | 窗口内无上报 |
| 清单排序 | 风险等级 → 预计天数升序 → 电量升序 → `device_id` |

窗口按 **UTC 自然日**（含当天），`days` 取 1–30。PostgreSQL 使用
`date_trunc('day', timezone('UTC', ts))`，避免会话时区为 Asia/Shanghai 时日期整体倒退一天；
SQLite 单测使用 `strftime('%Y-%m-%d')`，与 PG 分支同口径。

## Web

新增独立菜单页 `/battery-health`（所有角色可见）：

- 汇总卡：设备总数 / 平均电量 / 严重 / 预警 / 未知；
- 机队平均电量趋势（只画有数据的日期，缺数据不补点）；
- 续航风险清单：电量进度条、电压、衰减、预计到 15% 天数、未处理告警、最近上报与风险标签；
- 按分组汇总表；支持分组与 7/14/30 天窗口筛选；
- 风险总数超过 `limit` 时明确提示「仅展示最紧急的前 N 台，共 M 台」。

## 偏差与说明

- 修复了一条**既有时间敏感单测**：`test_stats_overview.py` 用 `now - 10min` 造数，
  在每小时前 10 分钟会跨小时桶而失败；改为写入当前时刻，与业务逻辑无关，不改生产代码。
- 设备端本次没有新增页面：续航看板是桌面运维视图，移动端已有概览/设备详情覆盖单台电量。
