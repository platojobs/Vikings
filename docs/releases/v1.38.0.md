# v1.38.0 · 告警规则条件树：可表达「且」的嵌套范围

> 发布日期：2026-11-13
> 定位：把 v1.35.0 的「单维度多值取或」升级为可表达交集的 **条件树**，
> 支持「标签 A 且 分组 B」「(标签A 或 标签B) 且 分组C」这类组合，
> 同时保证老规则的判定结果、裁决口径与回滚能力不变。

## 版本定位

- **条件树**：`alert_rule.conditions`（JSON/JSONB），`all`=且、`any`=或，叶子维度为
  `group / device / tag`；同一叶子内多值仍为「或」，与 v1.35.0 一致。
- **等价迁移**：`0013_rule_conditions` 把既有 group/device/tag 规则等价回填为单叶子 `any`，
  不改写 `scope_type / scope_value / scope_values`。
- **空树不放行**：空条件树返回 400；全局规则的唯一表达是 `scope_type=global` 且
  `conditions=null`，不存在「空树命中一切」的隐性行为。
- **裁决不变**：条件树只决定「是否命中」，同指标取最高级别、同级按 priority 再 id、
  每指标一条告警的规则保持不变。
- **历史可对照**：条件树变更写入既有审计 `changes.conditions = {from, to}`，
  Web 历史抽屉直接展示；超长时按 2000 字符截断并明确标记。
- **Web 可编辑**：规则编辑器支持且/或嵌套；老规则打开时显示等价条件树而不是空白。
- **移动端不受影响**：看板与告警中心只读规则结果，本轮不改规则编辑。

## 数据模型

### `alert_rule.conditions`（迁移 `0013_rule_conditions`）

```json
{
  "op": "all",
  "children": [
    {"op": "any", "children": [
      {"dim": "tag", "values": ["冷库"]},
      {"dim": "tag", "values": ["关键"]}
    ]},
    {"dim": "group", "values": ["华东"]}
  ]
}
```

| 约束 | 值 | 理由 |
| --- | --- | --- |
| 条件组层数 | ≤3（含最外层） | 覆盖「(A 或 B) 且 C」；再深难以解释与排障 |
| 叶子数 | ≤20 | 与单规则范围值总量同量级，求值恒定廉价 |
| 单叶子值 | ≤50 | 沿用 v1.35.0 上限 |
| 单值长度 | ≤64 字符（标签 32） | 与老字段、`device_tag` 校验一致 |

`scope_type` 增加 `custom`：真正嵌套的条件树无法用单值字段表达时使用；
单叶子条件树会镜像回 `scope_type=<dim>`、`scope_value=<首值>`、`scope_values=<全部值>`。

## 兼容与回滚

1. 迁移把 `scope_type` 为 group/device/tag 的行回填为
   `{"op":"any","children":[{"dim":<scope_type>,"values":<scope_values 或 [scope_value]>}]}`；
2. 老字段**原样保留**，downgrade 到 v1.35 后仍可读、可继续匹配；
3. 六种老形态（global / 单值 group / 单值 device / 多值 group / 多值 tag / 多值 device）
   在升级前后的判定结果逐条一致；
4. 嵌套 `custom` 规则回滚到 v1.35 后不命中（fail-closed），不会产生误报；
   需要回滚时先把它改回单维度范围；
5. 升级前后默认阈值、抑制窗口、SLA、通知路由与批量指令行为不变。

## 接口与权限

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/rules` | admin | 入参可带 `conditions`；传条件树时 `scope_type=custom` |
| PUT | `/api/rules/{id}` | admin | 只传 `conditions` 即更新条件树；传 `scope_type=global` 清空条件树 |
| GET | `/api/rules` | 登录可读 | 返回 `conditions`，老规则为 `null` |
| GET | `/api/rules/{id}/history` | 登录可读 | 复用既有审计，`changes.conditions` 含前后值 |

未登录 401；operator/viewer 写规则 403；未知维度、空叶子、空条件组、超深度、
条件树与 `scope_type` 冲突均返回 400 中文原因。

## 审计体积

单个字段值序列化后超过 2000 字符时，存为
`{"truncated": true, "chars": N, "preview": "<前2000字符>"}`；
规则字段本身不含密钥/口令，条件树可以安全记录前后值。

## 已知边界

- 条件树只支持 `group/device/tag` 三种维度，不引入指标值区间、时间窗口等新叶子；
- 条件组内不支持「恰好 N 个」这类计数语义；
- 移动端本轮不做规则编辑，只保证看板与告警中心展示不受影响。
