## 版本定位

一句话：**网关、数据库、Broker 任一层出问题，运维能在两分钟内从指标和日志判断出是哪一层。**

本轮只补可观测性与运维信号，不改业务功能、REST 业务契约与 MQTT 报文格式：

- JSON 结构化日志（可切人类可读）+ `X-Request-Id` 全链路追踪 + 敏感信息脱敏；
- `/api/health` 保持轻量存活；新增 `/api/health/ready` 真实查库 + MQTT 状态，未就绪 503；
- Prometheus `/metrics`：请求计数/耗时直方图/状态码、登录失败与 429、MQTT 连接与掉线、DB 错误与连接池；
- 生产反代透传请求 ID、记录上游耗时、`/metrics` 仅内网可达；
- 可直接加载的 Prometheus 告警规则，覆盖网关、MQTT、5xx、登录 429、DB、备份失败。

## 只读核对结论（改动前）

| 项 | 改动前 | 本轮处理 |
| --- | --- | --- |
| 日志 | `logging.basicConfig` 文本 + uvicorn 默认 access log，无请求 ID、无结构化字段 | 统一 JSON/文本格式，关闭 uvicorn access log，自建访问日志 |
| 健康检查 | `/api/health` 只查 MQTT 内存状态，不查库 | 保留存活语义；新增 `/ready` 分层探测 |
| 指标 | 无 | 新增 `/metrics` 与 13 类指标 |
| 请求追踪 | 无 | 接受/生成 `X-Request-Id`，响应头与错误体回写 |
| 反代日志 | 默认 combined 格式，无上游耗时/请求 ID | 自定义格式含 `rt/urt/rid/grid` |
| 容器健康 | 依赖 `/api/health` 的 `mqttConnected` | 改为 `/api/health/ready`（DB + MQTT） |
| 告警规则 | 无 | `infra/prometheus/iot-alerts.yml` |
| 脱敏 | 无日志脱敏逻辑 | `redact_text()` + 不记录请求头/体/查询串，单测覆盖 |

### 6. 脱敏证明

- `grep -c "<token>" gateway.log` 结果为 `0`；
- 单测还覆盖 `Authorization: Bearer`、`password=`、`postgresql://user:pass@host` 与异常堆栈脱敏。

## 偏差与遗留

1. `/metrics` 在网关自身不鉴权（仅容器网络可达），反代按私网段白名单放行；公网访问返回 403。
2. DB 连接池指标在 SQLite 下没有意义，统一记 0；生产 PostgreSQL 下反映真实池状态。
3. `iot_db_ready` 只有在 `/ready` 被探测时才更新；Prometheus 应同时配置 blackbox 探测 `/ready`，否则请以 `iot_db_query_errors_total` 为准。
4. 生产已验收后停机，数据卷保留；需要继续运行时执行 `./scripts/prod_up.sh`。
5. 告警规则未内置 Alertmanager 路由与静默策略，按实际值班渠道接入。
