# v1.11.0 发布说明

- 发布日期：2026-11-04
- 提交：本提交（附注标签 `v1.11.0` 指向该提交）
- 标签：`v1.11.0`

## 版本定位

一句话：移动看板切换为服务端分页与服务端筛选，拆掉「首屏 100 台」和「告警 pageSize=50」两个上限；网关只做纯增量，新增参数默认关闭、向下兼容。

本轮面向规模化：首屏只拉一页设备，滚动按需翻页；「有告警」筛选与卡片角标改用数据库层按设备聚合的未处理告警数；汇总卡改用服务端全量统计，不再因只看第 1 页而失真。

## 移动看板

- **服务端分页**：首屏 `GET /api/devices?page=1&pageSize=20`；设备区页脚进入视口自动请求下一页并原样追加，加载中显示「加载中…」，加载完显示「没有更多了」。不再一次性拉取 100 台。
- **搜索即请求参数**：关键词 300ms 防抖后作为 `keyword` 下发，并重置到第 1 页；状态筛选对应 `status=online/offline`，切换同样重置分页。
- **有告警改用聚合计数**：`hasAlert=true` 在数据库层筛选，`withAlertCount=true` 返回每设备 `open_alert_count`；卡片角标与筛选结果同源，不再依赖未处理告警列表前 50 条。
- **告警列表分页**：`GET /api/alerts?status=open&page=N&pageSize=20` 按页追加；标题「未处理告警（N）」使用服务端 `total`，未处理告警超过 50 条时也能完整计数与翻阅。
- **汇总卡服务端口径**：设备总数 / 在线 / 未处理告警取 `/api/stats/overview`，与设备分页的 `total` 分开；「筛选结果 N 台 / 全部 M 台」仍保留，筛选无结果时给出可读空状态且不清空汇总卡。
- **实时与分页协同**：MQTT 上报只更新已加载设备的数值与在线状态，不触发整页重拉；上下线事件即时改变「在线 / 离线」筛选结果；新设备或不满足当前页的设备不会即时插入，在下次刷新（下拉、切换筛选、轮询兜底）时按服务端分页出现。实时告警插入列表头条并递增对应已加载设备角标与服务端计数。
- **性能**：设备首屏固定 20 条，最新值只取已加载页设备（`/api/records/latest?deviceIds=...`），设备规模增长时首屏请求量基本恒定。
- **注入方式不变**：`storage` / `apiClient` / `realtimeService` 仍可注入，新增分页与聚合逻辑均有 Widget 测试覆盖。

## 网关接口（纯增量，默认关闭）

- `GET /api/devices` 新增两个可选参数：
  - `hasAlert`（默认 `false`）：只返回存在未处理告警的设备，按 `device_alert.status='open'` 在数据库层聚合，不受告警列表分页大小影响；
  - `withAlertCount`（默认 `false`）：每个设备条目额外返回 `open_alert_count`；不传时该字段为 `null`，既有字段语义不变。
- `GET /api/records/latest` 新增可选 `deviceIds`（逗号分隔、自动去重、单次最多 200 个）：只返回这些设备的最新值；传空串返回空数组。不传时仍返回全部设备各自最新一条。
- `/api/devices` 既有的 `status` / `keyword` / `group` / `page` / `pageSize` 与 `/api/alerts`、`/api/stats/overview` 均未改动。
- 汇总卡所需总量统计复用既有 `GET /api/stats/overview`（设备总数 / 在线 / 未处理告警），未新增统计端点。

## 已知限制

- 下拉刷新与筛选切换会重置到第 1 页，已加载的后续页不保留。
- 实时新增设备不会即时插入当前列表，需等下一次刷新；这是为避免打断滚动位置的明确取舍。
- 「有告警」筛选依赖本版本的 `hasAlert` / `withAlertCount` 参数，旧网关会忽略未知参数，需与 App 同步升级。
- 移动端设备详情的历史上报仍固定 `limit=10`，属于详情页范围，未在本轮做分页。
