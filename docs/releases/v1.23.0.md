> 发布日期：2026-11-05

## 版本定位

v1.23.0 不再是"再加一层测试"，而是把全项目唯一一条从未被 E2E 覆盖的核心业务链路
——**OTA 升级**——真实跑通，并在此过程中修掉 4 个会让任务永久 running/状态错乱的
产品缺陷。同时补上三类真实故障注入、把 PostgreSQL 作业从"只跑迁移"扩到核心用例、
交付一份可直接执行的真机验收清单。

## 发现并修复的产品缺陷

测试不是绕过去，而是先把产品修好再断言：

| # | 缺陷 | 修复 | 回归证据 |
| --- | --- | --- | --- |
| 1 | 设备无回执时，指令永久停在 `issued/progress`，OTA 任务永不收敛 | 新增后台「指令超时巡检」（`COMMAND_TIMEOUT_SECONDS` / `COMMAND_SWEEP_INTERVAL_SECONDS`），超时置 `failed` 并刷新任务汇总 | 巡检关闭时 E2E `ota_timeout_terminal` 在 15s 内拿到 `success=0 failed=0 state=issued` 而 FAIL；开启后 PASS |
| 2 | `apply_ack` 允许迟到的 `failed` 无条件覆盖 `success` | 终态不可回退：`success`/`failed` 后不再接受状态变化；`success` 强制 progress=100 | `test_terminal_state_does_not_regress_on_late_ack` 在旧逻辑下 `assert 'failed' == 'success'` 失败，修复后通过 |
| 3 | MQTT 下发异常只把指令置 failed，OTA 任务汇总仍为 0 | 下发失败即时计入 `failed` 并刷新汇总 | `test_dispatch_failure_counts_as_task_failed` |
| 4 | 回执未校验主题归属，设备 B 可推进设备 A 的指令 | `apply_ack` 接收主题 deviceId 并校验，不一致则忽略 + warning | `test_ack_cannot_advance_another_devices_command` |
| 4b | OTA 任务包含不存在设备时 total 永远凑不齐（僵尸任务） | 创建前校验设备存在性，缺失返回 400 | `test_ota_rejects_unknown_device_without_zombie_task` |

另外，`/api/health/ready` 的数据库探针从 `SELECT 1` 改为真实读取 `device` 表：
连接对象还在但库被独占锁/存储损坏时也能正确返回 503。

## OTA 端到端（E2E）

主链路（`ota_full_chain` + `ota_audit`）：

1. operator 调 `POST /api/ota/tasks` 创建设备任务；
2. 网关向 `device/{id}/cmd` 下发 `ota` 指令；
3. `scripts/simulate_device.py` 真实接收，回执 `received` 与
   `progress=[10, 30, 55, 80]`，最后 `success(100)`；
4. REST 任务变为 `success=1 failed=0`，设备 `state=success progress=100`，
   `firmware_version` 从 `1.0.0` 更新为 `1.1.0`；
5. 审计 `action=ota.create` 可查，含 operator、targetVersion、deviceCount。

失败路径：

- `ota_device_failure`：设备回执 `failed(progress=40)`，任务终态 `failed=1`，
  原因保留，固件**不被误标**为目标版本；
- `ota_timeout_terminal`：无回执设备触发真实后台巡检，任务在 15s 内 `failed=1`
  （测试仅回拨该指令的 `updated_at`，不改巡检逻辑），message 含超时秒数。

## 故障注入（真实断言）

| 场景 | 期望语义 | E2E 断言 |
| --- | --- | --- |
| 网关在 OTA 30% 时重启 | MQTT 非持久会话：停机期间的 progress=60、success、sensor seq=7777 **明确丢弃**；DB 进度持久；恢复后设备补发 success 自愈 | 重启后进度仍 30%、success/failed=0、seq=7777 不落库；补发 success 后 `success=1`、固件 1.3.0、seq=7778 入库 |
| 设备自身断连重连（Broker 不停） | 设备 offline→断开→同凭证重连 online；重连后新指令仍可下发与回执 | Broker 端口全程在；REST 状态 offline→online；重连后 config 指令回执 success |
| 数据库短暂不可用 | `/api/health` 仍 200（存活）；`/ready` 503 且 `components.database.ok=false`；网关不崩；恢复后继续服务 | SQLite 独占锁期间上述三项全部成立；释放后 `/ready` 200、`/api/devices` 可读 |

> 说明：E2E 的默认数据库是 SQLite，因此"数据库不可用"用独占锁复现；
> 它和 Postgres 连接失败一样，都会让真实读表失败并触发 503。

## 兼容性与迁移

- **无数据库迁移**：本次只改服务层与测试，表结构不变。
- 新增环境变量（均有默认值）：
  - `COMMAND_TIMEOUT_SECONDS=300`：指令无回执判失败的阈值；
  - `COMMAND_SWEEP_INTERVAL_SECONDS=60`：巡检周期。
  `infra/prod/.env.example` 与 `docker-compose.prod.yml` 已透传。
- API 新增语义：不存在设备的 OTA 创建返回 400；回执跨设备被忽略；终态不可回退。
  既有正常请求的请求/响应结构不变。

## 安全边界

- 回执归属校验防止设备改写其他设备的指令；
- OTA/指令日志只记录 cmdId、deviceId、state，不打印凭证；
- 真机清单中所有口令示例均为占位符。

## 偏差与遗留

- E2E 用 SQLite 独占锁模拟"数据库不可用"，未在 E2E 中起真实 PostgreSQL；
  Postgres 方言与核心用例由独立 CI 作业覆盖。
- 超时阈值默认 300s 与离线阈值一致；若单次 OTA 正常耗时接近该值，需按文档调大，
  否则会误判失败（真机清单 3.3 已列为验收项）。
- 真机清单是手工执行项，本次未在真实硬件上跑（仓库无实体设备）；E2E 用模拟器与
  真实 Broker 覆盖了协议与状态机，硬件侧需发布前按清单验收。
