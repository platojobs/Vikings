# v1.33.0 · 告警 SLA 闭环与值班交接

> 发布日期：2026-11-05
> 定位：告警「有通知、能确认」不等于「有人按时处理」。本次把响应时限、超时升级、
> 值班交接做成闭环：谁该处理、还剩多久、超时几次、换班后归谁，都能在 Web/移动端
> 与审计里查到真实证据。

## 版本定位

- **SLA 是快照，不是实时重算**：告警创建时按级别写入 `sla_minutes` 与
  `sla_deadline_at`。之后改阈值只影响新告警，存量不被追溯改写，避免历史口径漂移。
- **三态 + 两个过渡态**：已确认分 `met`（按时）与 `late`（超时达成），未确认分
  `pending` 与 `overdue`；历史确认但无 `acked_at` 的行单列 `unknown`，**不计达标**。
- **升级复用 v1.31.0 通知链路**：不新增通道、不绕过规则与重试队列，只新增
  `kind=escalation` 的投递与载荷字段。
- **交接不洗白 KPI**：只改责任人，不重置 SLA 计时与升级计数。

## 判定口径

| `sla_state` | 条件 | 达标 |
| --- | --- | --- |
| `met` | 已确认且 `acked_at <= sla_deadline_at` | 是 |
| `late` | 已确认且 `acked_at > sla_deadline_at` | 是（超时达成） |
| `unknown` | 已确认但 `acked_at IS NULL`（v1.21.0 前的历史行） | **否** |
| `overdue` | 未确认且已过截止时间 | 否 |
| `pending` | 未确认且未到截止时间 | 否 |

**历史行归类（取舍）**：v1.21.0 之前确认的告警没有 `acked_at`，无法证明是否按时。
默认算「达标」会把无法证明的处置当成合规，因此归为 `unknown` 且不计入任何达标统计；
迁移只回填 `sla_minutes` 与 `sla_deadline_at`，**不回填 `acked_at`/`assignee`**。

**按级别时限**：`critical_minutes`（默认 30）与 `warning_minutes`（默认 120），
在系统设置中由 `admin` 在线修改。

## 超时升级

- **策略：逐级升级 + 上限（二选一中的此项）**。第 N 次升级在
  `sla_deadline_at + (N-1) * escalation_interval_minutes` 触发；
  `max_escalations` 为上限（默认 2，0 表示不升级）。
- 选它而不是「首个超时点连续发 N 条」：给值班人真实处理间隔，避免同一秒轰炸；
  上限防止长期无人处理时无限重复。**达上限后停止升级，但 SLA 保持 `overdue`**。
- **同一条告警同一次升级只发一次**：巡检用条件更新原子领取名额
  （`WHERE escalation_count = N-1`），先写 `notification_delivery` 再提交，重启后续投。
- 通知内容可看出「超时升级、第几次、原 SLA 多久」：`attempt` / `maxAttempts` /
  `slaMinutes` / `deadlineAt` / `overdueMinutes`；SMTP 主题含「超时升级 第N/M次」。
- 无规则命中或通知总开关关闭时记 `suppressed`，不发送但可在投递历史看到原因。

## 值班交接

| 项 | 行为 |
| --- | --- |
| 范围 | 未处理 +（责任人=交班人或未指派且勾选「包含未指派」）；不碰他人名下告警 |
| 落库 | `assignee` 批量更新为目标值班人 |
| 审计 | 一条 `alert.handover`：交接人、接收人、条数、时间窗口、备注摘要 |
| 通知 | 给接收人**一条**汇总（`alert.handover`），不按告警逐条发送 |
| 计时 | **不重置** `sla_deadline_at` 与 `escalation_count` |

**是否重置计时（取舍）**：选择不重置。换班只是责任人变化，若重置会让同一问题
不断获得新的宽限期、并把已发生的升级「洗掉」，KPI 与巡检都失真；交接后仍能看到
原截止时间与已升级次数，处理紧迫性不被稀释。

## Web 与移动端

- Web 告警页：概览卡新增「其中已超时」；列表新增 SLA 列（状态标签 + 剩余/超出时长 +
  响应时长）、责任人列；支持「已超时」等筛选；「值班交接」入口带二次确认。
- 系统设置：SLA 阈值、升级上限与间隔可配（仅 admin 可保存）。
- 移动端告警中心：状态旁展示 `已超时`（红）/`超时达成`（橙）/`历史确认`（灰）徽标；
  移动端**只读展示 SLA**，不做交接（交接涉及跨班责任人变更与审计，统一在 Web 完成）。

## 偏差与说明

- `scripts/verify_sla_v133.py` 第一版在网关启动后立即落库，巡检用默认配置（通知总开关
  尚未开启）抢先升级并写 `suppressed`。改为**先配置通知与 SLA，再落库告警**后复现
  真实链路；这是验证脚本时序问题，不是生产逻辑问题。
- 迁移用 `sla_minutes` 快照回填存量告警（critical=30 / 其它=120），无法得知历史
  `acked_at` 的不做臆测，保持 `NULL`。
- 升级巡检默认 30 秒一轮（`SLA_SWEEP_INTERVAL_SECONDS`），不进入 v1.31.0 的投递
  重试循环，避免长任务互相阻塞。
