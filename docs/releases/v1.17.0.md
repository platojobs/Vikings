# v1.17.0 发布说明

- 发布日期：2026-11-05
- 提交：本提交（附注标签 `v1.17.0` 指向该提交）
- 标签：`v1.17.0`
- 对应交付项：`docs/delivery-readiness.md` 的 **P0-3（Broker 匿名接入、设备无凭证/无 ACL）**

## 版本定位

一句话：让「陌生人连上 1883/9001」什么也读不到、也发不出能冒充设备的消息；
每台设备只碰自己的 Topic。

本轮只做鉴权与凭证治理，不改业务功能与报文格式：
Broker 双监听关闭匿名、设备凭证签发/轮换/吊销、Web 与移动端独立只读凭证、
ACL 最小权限、脚本与客户端适配、鉴权矩阵文档。

## 只读核对结论（改动前 → 改动后）

| 项 | 改动前 | 本轮结论 |
| --- | --- | --- |
| Broker 匿名 | `mosquitto.conf` 的 1883/9001 均 `allow_anonymous true` | 两个监听均 `allow_anonymous false`，`per_listener_settings true` |
| 鉴权文件 | 无 `password_file` / `acl_file` | 1883 → `passwd` + `acl.device`；9001 → `passwd` + `acl.client` |
| 设备身份 | 无凭证字段，任何匿名客户端可伪造 `device/<id>/*` | 用户名恒等于 `deviceId`，凭证可签发/轮换/吊销，`Device` 表只存元数据与指纹 |
| 网关身份 | 虽有 `MQTT_USERNAME/PASSWORD` 配置，但 Broker 不校验 | `iot-gateway` 独立账号，按跨设备读 + 指令/系统事件写授权 |
| Web / 移动端 | 匿名连接 9001 订阅全部设备 Topic | 登录后换取各自独立只读凭证；ACL 无任何 write |
| 客户端降级 | 连不上就匿名/重试 | 取不到凭证保持未连接并重试，**不匿名降级**；移动端失败降级 REST 轮询 |
| 启动脚本 / 模拟器 | `start_all.sh` 直启 Broker；`simulate_device.py` 匿名 | 启动前自动初始化凭证并注入环境变量；模拟器无口令直接拒绝运行 |
| E2E | 复用外部 Broker，无法验证匿名与越权 | 强制自起临时 Broker 与随机凭证，新增匿名拒绝、跨设备隔离、客户端只读、轮换失效 |
| 密钥入库 | 无口令文件（因为没有） | `passwd`、状态文件加入 `.gitignore`；仓库只放 ACL、配置模板与生成脚本 |

## 主体—Topic 矩阵（真实 Broker 验证）

| 主体 | 监听 | 可读 | 可写 |
| --- | --- | --- | --- |
| `iot-gateway`（网关） | 1883 | `device/+/sensor/report`、`device/+/status`、`device/+/cmd/ack` | `device/+/cmd`、`device/system/alert`、`device/system/group`、`gateway/status` |
| 设备 `<deviceId>` | 1883 | `device/<deviceId>/#`（自己的整棵子树） | `device/<deviceId>/sensor/report`、`status`、`cmd/ack` |
| `web-console` | 9001 | `device/+/sensor/report`、`device/+/status`、`device/+/cmd/ack`、`device/system/alert`、`device/system/group` | 无 |
| `mobile-console` | 9001 | 同上 | 无 |
| 匿名 | 1883 / 9001 | 无 | 无（CONNACK 拒绝） |

隔离要点：

- 设备不能发布 `device/<id>/cmd`，指令只能由网关下发；
- 设备不能写 `device/system/*`，告警/分组事件由网关产生；
- 设备 A 即使订阅设备 B 的 Topic，投递阶段也会被 ACL 过滤；
- Web/移动端即使拿到设备口令，也只能走 9001，而 9001 的 ACL 没有 write 规则。

## 凭证生命周期

1. **初始化**：`python scripts/mqtt_credentials.py init --device-id dev-0001`
   生成 `infra/mosquitto/passwd`（PBKDF2-SHA512 hash，0600）与服务/客户端账号。
2. **首次签发**：`POST /api/devices/{deviceId}/mqtt-credential` 或
   `scripts/mqtt_credentials.py issue --subject device:dev-0001 --reload`。
   口令只在响应/命令输出中出现一次，设备应立即写入安全存储。
3. **轮换**：同一接口/命令再次调用即生成新口令并覆盖旧值；Broker 重载后旧凭证立即失效。
4. **吊销**：`scripts/mqtt_credentials.py revoke --subject device:dev-0001 --reload`。
5. **持久化边界**：Broker `passwd` 存 hash；`device` 表存 `mqtt_username`、
   `mqtt_credential_version`、SHA-256 `fingerprint`、签发/轮换时间，**不存明文**；
   本机 `.run/mqtt/credentials.json`（0600，不入库）仅供开发脚本读取。

## 新增 / 变更配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MQTT_USERNAME` | 空（开发脚本注入 `iot-gateway`） | 网关 Broker 身份，生产必须为 `iot-gateway` |
| `MQTT_PASSWORD` | 空 | 网关 Broker 口令，生产必填 |
| `MQTT_PASSWORD_FILE` | `infra/mosquitto/passwd` | 网关签发设备凭证时写入的密码文件 |
| `MQTT_RELOAD_COMMAND` | 空 | 签发后重载 Broker 的命令；留空则读 `.run/mosquitto.pid` 发 SIGHUP |
| `MQTT_WEB_USERNAME` | `web-console` | Web 只读主体 |
| `MQTT_WEB_PASSWORD` | 空 | Web 只读口令，生产必填；未配置时凭证接口 503 |
| `MQTT_MOBILE_USERNAME` | `mobile-console` | 移动端只读主体 |
| `MQTT_MOBILE_PASSWORD` | 空 | 移动端只读口令，生产必填；未配置时凭证接口 503 |
| `MQTT_DEVICE_PASSWORD` | 空 | 模拟器设备口令（也可用 `--password`）；缺失时模拟器直接报错 |

生产启动校验新增：网关身份必须为 `iot-gateway`，且 `MQTT_PASSWORD`、
`MQTT_WEB_PASSWORD`、`MQTT_MOBILE_PASSWORD` 均不能为空。

## 兼容与迁移

- **已有部署**：先 `mqtt_credentials.py init` 生成 `passwd`，再给每台存量设备签发凭证，
  然后配置网关/客户端口令并完整重启 Broker 与网关。缺少 `passwd` 时 Broker 会启动失败，
  这是预期行为。
- **Docker**：`infra/mosquitto/` 整目录挂载到 `/mosquitto/config` 并设置工作目录；
  启动前必须先初始化凭证。重载用 `docker compose ... kill -s HUP mosquitto`。
- **设备端**：设备模拟页新增「MQTT 口令」；用户名固定为设备 ID。
  模拟器使用 `--username` / `--password` 或 `MQTT_DEVICE_USERNAME` / `MQTT_DEVICE_PASSWORD`。
- **Web / 移动端**：登录后先调 `GET /api/auth/mqtt-credentials` 再连接 Broker；
  未登录或服务端未配置时不会匿名连接。
- **接口兼容**：新增两个接口与可选字段，既有 REST 入参/响应语义不变；
  MQTT Topic 与报文格式不变。唯一行为变化是「匿名连接不再可用」。

- `gateway/.venv/bin/python -m pytest -q`：**87 passed**（新增 9 条凭证用例）。
- `flutter analyze`：`No issues found!`
- `flutter test`：**67 passed**（`All tests passed!`）。
- `web npm run test`：**7 passed**；`npm run build`：成功。
- `scripts/e2e/e2e_acceptance.py`：**25/25 PASS**，关键输出：
  - `mqtt_auth_isolation`：匿名 1883/9001 均被拒（rc=135/135）；
    设备 A 订阅 B 的 SUBACK granted 但**收不到 B 的消息**；A→B 发布未被 B 收到；
    web/mobile 可订阅但发布被拒；轮换后旧凭证 rc=135、新凭证 rc=0；
  - `realtime_report` / `realtime_status` / `realtime_alert` / `command_*` 等既有项全部 PASS；
  - 降级与恢复：停 Broker → REST 可用；重启 Broker → WS 重连、网关 `mqtt.connected=true`。

> Mosquitto 对 ACL 拒绝的订阅可能仍返回 SUBACK granted（协议允许），
> 因此验收以「越权后是否收到消息」判定隔离，而不是只看 SUBACK。

## 偏差与运维影响

1. **设备凭证签发是显式步骤**：注册接口仍只建设备元数据，注册后需调用
   `POST /api/devices/{deviceId}/mqtt-credential`（或 CLI）签发凭证。这样批量注册不会
   一次返回 200 个口令，但要求运维在设备首次接入前完成签发。
2. **单密码文件承载全部主体**：设备、网关、Web、移动端共用 `passwd`，靠用户名区分；
   删除/新增账号需要重载 Broker。设备规模很大时可评估按租户/分组拆文件。
3. **客户端凭证是长期静态口令**（服务端 env），不是短期 token；泄露后需人工轮换
   `MQTT_WEB_PASSWORD` / `MQTT_MOBILE_PASSWORD` 并重载 Broker。短期凭证属于后续增强。
4. **轮换依赖 Broker 重载**：签发接口返回 `reloaded=false` 时旧口令仍有效；
   生产必须配置 SIGHUP 或 `MQTT_RELOAD_COMMAND` 并纳入巡检。
5. **网关需要对 `infra/mosquitto/` 有写权限**（后台签发路径）；无写权限时改用宿主机 CLI。
   口令文件使用 PBKDF2-SHA512 + 12 字节盐，兼容 Ubuntu 自带的 Mosquitto 2.0.x
   （只接受 12 字节盐）与 2.1.x（接受 12/64）；CI 首次运行曾因 64 字节盐被 2.0.x 拒绝，
   已修正。
6. **E2E 不再复用外部 Broker**：本地运行前需停掉 `start_all.sh` 托管的 Broker，
   否则脚本会因端口占用直接失败（避免误测外部匿名 Broker）。
7. `Device.mqtt_credential_fingerprint` 只用于对账，无法反推口令；平台不提供口令二次查看。

## 遗留项与下一步

1. P0-1：生产部署入口（Dockerfile / 反代 / HTTPS）——当前唯一交付阻断项。
2. 客户端短期 MQTT 凭证（登录换取短 TTL token + 刷新）替代长期静态口令；
   可结合 Broker 的动态安全插件或每次签发新客户端账号。
3. 凭证操作审计已记录 `device.credential_issue`，后续可在 Web 设备详情展示
   版本/轮换时间并提供一键轮换按钮。
4. 多实例网关下，签发应保证只有一个实例写 `passwd`；大规模部署建议由独立凭证服务负责。
