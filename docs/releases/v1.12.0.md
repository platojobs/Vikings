# v1.12.0 发布说明

- 发布日期：2026-11-04
- 提交：本提交（附注标签 `v1.12.0` 指向该提交）
- 标签：`v1.12.0`

## 版本定位

一句话：移动看板新增分组切换与分组筛选，与搜索、状态筛选、有告警、服务端分页组合生效；空分组统一归入「未分组」。

本轮在 v1.11.0 服务端分页的基础上补齐分组维度：分组概览来自网关既有 `/api/devices/groups`，切换分组作为 `group` 请求参数下发并重置到第 1 页，不引入新的客户端过滤，也不破坏既有分页与告警聚合口径。

## 移动看板

- **分组切换**：筛选区新增一行分组 chips（`全部分组` + 各分组），数据来自 `GET /api/devices/groups`；切换后重置到第 1 页并携带 `group=<组名>`。
- **与既有筛选组合**：分组与关键词、在线 / 离线、有告警同时作为请求参数下发；组合筛选的 `total` 由服务端返回，汇总卡仍展示全量口径与「筛选结果 N 台 / 全部 M 台」。
- **无分组兜底**：设备 `group_name` 为空串时统一显示为「未分组」，分组概览中也归入同一桶；选择「未分组」时下发 `group=未分组`，网关匹配空串与字面「未分组」。
- **分页不回归**：分组切换重置到第 1 页；滚动加载、加载中状态、「没有更多了」与 v1.11.0 保持一致。
- **实时协同不变**：MQTT 上报只更新已加载设备，不触发整页重拉；分组变化属于设备元数据，下一次刷新时按服务端分页结果生效。
- **注入方式不变**：`storage` / `apiClient` / `realtimeService` 仍可注入，新增分组逻辑均有 Widget 测试覆盖。

## 网关接口（最小增量，默认行为不变）

- `GET /api/devices` 的 `group` 参数沿用既有实现，v1.12.0 只补充语义：`group=未分组` 时匹配 `group_name` 为空串或字面「未分组」的设备。
- `GET /api/devices/groups` 把空分组名与「未分组」合并为同一个 `未分组` 桶，`total` / `online` / `offline` 累加；普通分组不变。
- 不传 `group` 时设备列表与分组概览行为、排序、总数均与 v1.11.0 一致，并补了回归断言。

## 已知限制

- 分组列表来自 `/api/devices/groups`，设备分组变更后需下一次刷新（或切组）才能反映到 chips。
- 分组筛选与「有告警」组合时，`total` 为服务端组合条件后的结果，汇总卡仍为全量统计，两者口径按设计分离。
- 「未分组」是展示层归并，不改变数据库中的 `group_name` 原值。
- 移动端设备详情的历史上报仍固定 `limit=10`，未在本轮做分页。

## 发布流程

2. CI 全绿后才创建附注标签 `v1.12.0` 并推送；
3. 未重指、未移动、未删除任何历史标签。

## 升级建议

- 网关与 Web 后台为向后兼容改动，现有调用方无需调整。
- 移动端更新后可直接按分组筛选；建议与 v1.11.0 及以上网关配套，以复用服务端分页与告警聚合计数。
