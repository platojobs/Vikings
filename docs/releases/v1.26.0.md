# v1.26.0 · 凭证可运维化 + 搜索体验补齐

> 发布日期：2026-11-05
> 定位：把「只能在命令行轮换设备凭证」补成界面可运维能力，并关闭 v1.25.0 记录的两处搜索体验缺口。

## 版本定位

- **凭证可见化**：Web 与移动端设备详情都能看到凭证是否签发、版本、最近轮换时间、是否吊销；
  只展示指纹前 8 位，**绝不返回/渲染口令明文或完整指纹**。
- **受控轮换**：admin 可在界面轮换/吊销；operator 仍可首次签发，但不能覆盖已有有效凭证。
- **失败不说谎**：Broker 重载失败时明确提示「已写入新凭证但 Broker 未重载，旧凭证可能仍然有效」，
  并给补救步骤；审计记录 `result` 而不只是动作。
- **搜索加载更多**：移动端设备筛选不再只显示前 4 台，可滚动查看已加载结果并继续加载更多。

本版本新增 **1 个 Alembic 迁移**（`0005_device_cred_revoked`，仅加一列，可空），
新增 **1 个吊销端点**（`DELETE /api/devices/{deviceId}/mqtt-credential`）；
签发/轮换仍复用既有 `POST` 端点，只扩展响应字段，没有第二套轮换接口。

## 凭证状态与权限

| 项 | 行为 |
| --- | --- |
| 状态口径 | `missing`（未签发）/ `active`（有效）/ `revoked`（已吊销），由服务端计算 |
| 展示字段 | 用户名、版本、首次签发、最近轮换、吊销时间、指纹前 8 位 |
| 未签发提示 | Web/移动端均显示「该设备尚未签发凭证，无法接入 Broker」，并给签发入口 |
| 首次签发 | operator+admin（沿用既有权限） |
| 轮换/吊销 | 仅 admin（v1.26.0 收紧）；operator 调用轮换返回 403 并说明原因 |
| 指纹 | `DeviceOut` 只返回 `mqtt_credential_fingerprint_prefix`（8 位），用于人工对账 |

判断理由：首次签发只是建立身份，不打断在线设备；轮换会改变口令、吊销会删除 Broker 账号，
两者都会让设备下一次重连失败，属于破坏性操作，因此收敛到 admin，operator 保留日常开通能力。

## 轮换流程与一次性口令

1. 二次确认写清真实影响：旧凭证对新连接立即失效、已建立的连接可能维持到下次断线、
   设备必须更新配置、Broker 未重载时旧凭证可能仍有效。
2. 确认后弹出一次性口令，提供「复制口令」，且只能通过「我已保存，关闭」退出；
   关闭后界面与服务端都无法再查（服务端只保存 SHA-256 指纹），需要新口令只能重新轮换。
3. Web 对话框禁用遮罩点击、ESC 与右上角关闭；移动端 `barrierDismissible=false` + `PopScope`。
4. 移动端与 Web 都会在轮换后重新拉取设备详情，避免显示过期的版本/指纹前缀。

## Broker 重载失败的真实语义

- `reloaded=false` 时接口仍返回 200 与口令（否则调用方拿不到已写入的新凭证），
  但界面按失败处理并展示：**「已写入新凭证，但 Broker 未重载，旧凭证可能仍然有效」**。
- 补救：宿主机 `systemctl reload mosquitto` / `$COMPOSE restart mosquitto`，确认后让设备改用新口令；
  持续失败则先吊销旧账号，修复 Broker 后重新签发。
- 审计 `device.credential_issue` 增加 `operation`、`reloaded`、`reload_detail`、`result`
  （`reload_ok` / `reload_failed`）；吊销同理写 `device.credential_revoke`。
- Broker 密码文件重载**不会**强制断开已建立的 MQTT 会话；旧凭证对新连接立即失效，
  已连接设备可能维持到下次断线，因此界面的确认文案不再声称「当前连接会立即被断开」。

## 搜索体验补齐

| 项 | 行为 |
| --- | --- |
| 结果展示 | 下拉面板用 280px 可滚动区域展示**全部已加载结果**（不再只显示 4 条） |
| 加载更多 | 底部显示「共 N 台匹配，已加载 M 台」，并提供「加载更多（还有 N-M 台）」 |
| 分页 | 每页 20，按 `page` 递增追加并按设备 ID 去重；`total` 来自服务端，不静默截断 |
| 结束态 | 全部加载后提示「共 N 台匹配，已全部加载」 |
| 并发保护 | 沿用 `_deviceSearchSeq`，新关键词会丢弃旧分页响应；加载中重复点击不重复请求 |

本能力只在移动端告警中心页面存在；Web 设备列表本身已有分页与关键词搜索，
因此搜索用例在 Flutter Widget 测试中完成，不额外增加 E2E 浏览器操作。

## 兼容与升级

- 升级：执行 `alembic upgrade head` 即可（新增列可空，存量设备视为「未吊销」）。
- 既有 `POST` 响应新增 `operation` 字段；老客户端忽略该字段不受影响。
- 首次签发权限不变；若原流程依赖 operator 轮换，需要改用 admin 或命令行。
- Web/移动端展示新增字段全部可空，旧服务端响应不会导致崩溃。

## 明确未覆盖（需要用户侧动作）

- 真机验收：`docs/device-acceptance.md` 第 2 节的界面轮换/重载失败步骤需在真实设备与真实 Broker 上执行。
- 生产环境的 `MQTT_RELOAD_COMMAND` 仍未在云主机配置；生产轮换后可能返回 `reloaded=false`，
  需按 `docs/operations.md` 3.1.3 手工重载。
- 生产 secrets（移动端签名）与定时备份/日志聚合仍属于运维侧动作，本版本未改变。
