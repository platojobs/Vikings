## 版本定位

一句话：让「仓库被拿去生产部署」时，默认配置不再能直接登进去。

本轮是交付阻断项治理，不改业务功能：生产环境启动校验、演示账号受控、登录限流、
口令强度校验；登录成功响应与既有鉴权语义保持不变。

## 只读核对结论

| 项 | 改动前现状 | 本轮结论 |
| --- | --- | --- |
| JWT 密钥 | `config.py` 默认 `change-me-in-production`，`.env.example` 公开开发密钥 | 生产启动校验长度与已知弱值，不通过即拒绝启动 |
| 管理员口令 | 默认 `admin123`，所有环境可直接登录 | 生产校验弱口令；开发保留默认但打印 warning |
| 演示账号 | 表为空时无条件种子 operator/viewer | 仅在开发/测试默认种子；生产默认关闭，`SEED_DEMO_USERS=true` 才显式开启 |
| 登录防护 | 无失败计数、无锁定、无限流 | 进程内按 IP + 账号计数，超限 429 + `Retry-After`，成功清零 |
| 口令策略 | 新建/重置仅要求 6 位 | 默认至少 8 位，并拒绝常见弱口令；既有账号不受影响 |
| 数据库默认值 | 生产可直接使用 SQLite / `iot_pass` | 生产启动拒绝 SQLite 与默认/弱口令数据库账号 |
| HTTP 错误响应 | 自定义异常处理会丢 `headers` | 保留 `HTTPException.headers`，429 能带 `Retry-After` |
| 数据库日志 | 启动日志直接打印含口令的 URL | 改为脱敏输出 `***` |
| 既有接口 | 登录 200/401、鉴权 401/403 结构稳定 | 保持不变；429 是新增分支，已写入 contracts |

## 行为变化

1. **生产 fail-fast**
   - 显式环境变量 `APP_ENV=production`（`development` / `test` / `production`）。
   - 启动时校验：`JWT_SECRET` ≥ 32 位且不是仓库公开默认值；`ADMIN_PASSWORD` ≥
     `PASSWORD_MIN_LENGTH` 且不是常见弱口令；`DATABASE_URL` 必须 PostgreSQL 且口令 ≥ 8 位、
     不是 `iot_pass`。
   - 任一项不合规：抛出可读的 `RuntimeError`，网关不启动，错误逐条列出原因。
   - 开发/测试：允许默认值，启动日志输出「安全配置提醒」，不会因默认配置无法启动。

2. **演示账号受控**
   - `SEED_DEMO_USERS` 未设置：开发/测试写入 operator/viewer，生产不写入。
   - `SEED_DEMO_USERS=true`：生产也写入，但日志打 warning 提醒尽快替换或停用。
   - `SEED_DEMO_USERS=false`：任何环境都不写入。
   - 种子仍只在账号表为空时执行；已有账号的环境升级后账号不消失、口令不被覆盖。

3. **登录限流**
   - 维度：直连客户端 IP + 用户名；默认 5 次失败 / 300 秒窗口 / 锁定 900 秒。
   - 达到阈值后的尝试返回 HTTP 429，响应头 `Retry-After` 为剩余秒数，响应体沿用统一结构。
   - 成功登录立即清零该维度计数；不同账号互不影响。
   - 账号不存在、停用与口令错误仍在 401 统一提示，不泄露账号是否存在。

4. **口令强度**
   - 新建账号与重置口令：最小长度取 `PASSWORD_MIN_LENGTH`（默认 8），并拒绝常见弱口令表。
   - 不合规返回 400 + 可读文案；既有账号的口令不做回溯校验。

## 新增 / 变更配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_ENV` | `development` | `production` 时启用启动安全校验 |
| `SEED_DEMO_USERS` | 未设置 | `true/false` 显式开启/关闭演示账号；未设置时按环境决定 |
| `PASSWORD_MIN_LENGTH` | `8` | 新建/重置账号的最小口令长度 |
| `LOGIN_MAX_FAILURES` | `5` | 窗口内允许的失败次数 |
| `LOGIN_FAILURE_WINDOW_SECONDS` | `300` | 失败计数窗口 |
| `LOGIN_LOCKOUT_SECONDS` | `900` | 达到阈值后的锁定秒数 |

`gateway/.env.example` 已同步；生产部署前的完整必改项见 README「4.2.1」。

## 兼容性与影响

- 登录成功响应仍为 `{token, user:{username, role}}`，鉴权失败仍为 401/403，无破坏性改动。
- 生产环境若沿用旧默认配置会**无法启动**，这是预期行为；按启动错误逐条替换即可。
- 开发环境 `start_all.sh` / E2E / 移动端演示账号路径保持不变。
- 账号管理接口对短口令/弱口令的拒绝由 Pydantic 422 调整为业务 400 + 文案，
  便于前端直接展示原因；请求字段结构不变。
- 限流为实现取舍：内存计数、多进程不共享、重启清零；详见「遗留项」。

## 遗留项与下一步

1. **限流是进程内实现**：多进程/多副本下阈值被放大，重启清零；生产建议在反代层
   （nginx `limit_req`）或 Redis 中做全局限流，并明确可信代理的真实 IP 获取方式。
2. `X-Forwarded-For` 默认不信任，网关直连部署时按直连 IP 计数；上反代后需在反代层限流。
3. 无 refresh token / 服务端吊销，token 泄露后在 TTL（默认 720 分钟）内仍有效，
   属于 P2-4，后续版本处理。
4. Web 登录页仍预填演示账号快捷入口，生产应通过构建环境隐藏或移除（建议纳入 P1/P2）。
5. 下一项 P0：P0-3 Broker 匿名接入与设备凭证，随后 P0-1 生产部署入口。
