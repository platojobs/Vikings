# v1.35.0 · 设备标签体系 + 告警规则范围扩展 + 规则变更历史

> 发布日期：2026-11-07
> 定位：把 v1.34.0 遗留的「范围只能单值匹配」和「规则变更无法对照历史」补齐，
> 并让标签成为设备管理、筛选、导出与告警规则共用的维度。

## 版本定位

- **标签成为一等维度**：新增 `device_tag` 关联表，单设备多标签；设备列表、告警列表、
  两类 CSV 导出、Web 与移动端筛选、告警规则范围都读同一份标签。
- **规则范围从单值到多值**：保留 `scope_value`（首值）兼容旧客户端与 downgrade，
  新增 `scope_values`（数组）作为权威输入；**同一条规则内多个值之间为「或」**。
- **历史不另造一套记录**：规则变更历史直接读既有 `audit_log`，并在审计 `detail` 中
  增加 `changes: {字段: {from, to}}`，阈值等数值可对照前后值。
- **行为不漂移**：不传标签的列表/告警/导出与升级前完全一致；旧单值规则、无标签设备、
  按分组筛选的行为不变。

## 数据模型

### `device_tag`（新表）

| 字段 | 说明 |
| --- | --- |
| `device_id` | 设备 ID，与 `device.device_id` 一致 |
| `tag` | 标签字符串 |
| `created_at` / `created_by` | 打标签时间与操作人 |

- 复合主键 `(device_id, tag)`：数据库层强制同一设备同一标签不重复。
- 索引 `(tag, device_id)`：按标签筛选设备、按标签统计设备数均可走索引。
- 约束：单标签 ≤32 字符；单设备 ≤16 个标签；单次请求 ≤200 台设备、≤50 个标签；
  字符集 `A-Za-z0-9_-` 与中文；空、纯空白、超长、非法字符返回 400 可读原因。
- **为什么用关联表而不是数组列**：SQLite（测试）与 PostgreSQL（生产）行为一致；
  数组列在 SQLite 只能存 JSON 文本、无法建普通索引，重复标签也无法在数据库层约束。

### `alert_rule.scope_values`

- `scope_type` 新增 `tag`，取值 `global / group / device / tag`。
- `scope_values` 为 JSON/JSONB 字符串数组；`scope_value` 保留并存首个值。
- 迁移 `0010_device_tags` 回填老规则：`scope_values=[scope_value]`（`global` 保持 `null`）。
- 匹配时优先读 `scope_values`，为空再回退 `scope_value`；downgrade 后 `scope_value`
  仍是原值，旧代码可继续工作。

## 范围语义

1. **组内「或」**：一条规则内的多个分组/设备/标签，命中任一即适用。
2. **组间「或」**：同一指标多条规则命中，仍按 v1.34.0 取最高级别（同级按 `priority`、`id`）。
3. **维度不混填**：分组、设备、标签不能混在同一条规则的 `scope_values`，混填返回 400。
4. 当前不提供「分组 A 且 标签 B」的交集规则；需要更细粒度时用设备 ID 或拆分规则。

选择理由：标签是并列管理维度，交集会让多标签规则趋近空集且难以解释「为什么没命中」；
「或」与多值筛选的预期一致，也便于用单台设备真实上报验证。

## 接口与权限

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/devices/tags` | 登录可读 | 标签与设备数 `[{tag, device_count}]` |
| POST | `/api/devices/tags/batch` | admin | 批量打/移除标签，逐台返回结果 |
| GET | `/api/devices` | 登录可读 | 新增可重复 `tag` 参数（或语义） |
| GET | `/api/alerts` | 登录可读 | 新增可重复 `tag` 参数（或语义） |
| GET | `/api/exports/records` | operator/admin | 新增可重复 `tag` 参数 |
| GET | `/api/exports/alerts` | operator/admin | 新增可重复 `tag` 参数 |
| GET | `/api/rules/{id}/history` | 登录可读 | 规则变更历史（来自审计） |

- **标签写仅 admin**：标签会改变规则命中范围与导出范围，影响面接近「改规则」；
  operator 仍可执行设备指令与告警确认，但不能批量改标签。viewer 全部只读。
- 批量结果逐台状态：`updated` / `unchanged` / `not_found` / `over_limit`；
  重复标签与移除不存在的标签为幂等 `unchanged`；超上限整台跳过，不做「加一半」。
- 未登录访问上述端点统一 401。

## 兼容性

- **同一批上报样本**：迁移只建表/加列与回填，不改规则阈值；v1.34.0 的 36 组边界样本
  在升级前后判定一致（`gateway/tests/test_alert_rules.py` 与
  `scripts/verify_tags_v135.py` 均覆盖）。
- **旧单值规则**：`scope_value` 保留，`scope_values` 回填后等值匹配；不修改规则时行为不变。
- **无标签设备**：`tags=[]`；不传 `tag` 的列表/告警/导出 SQL 不变。
- **按分组筛选**：`group` 语义未动，回归断言保留。
- **downgrade**：删除 `device_tag` 表与 `scope_values` 列；`scope_value` 仍在，旧版本可读。

## 验证

- 迁移三场景（空库 upgrade、v1.34 既有库 upgrade、downgrade 往返）——真实 PostgreSQL + Alembic。
- 真实上报：按标签命中、非命中、多值「或」、多条件组合——真实 Broker + uvicorn + HTTP。
- 批量部分失败：不存在设备、重复标签、超上限逐类可见。
- 列表与导出：标签筛选后的真实行数与 `count` 一致。
- 移动端：Widget 测试覆盖标签 + 关键词 + 状态组合与重置第 1 页；
  不放进 E2E 的原因：E2E 走真实网关与 Broker，环境里批量造标签会污染共享数据，
  且移动端筛选是纯前端参数拼装 + 服务端筛选，Widget 测试已覆盖参数与状态机。
- 规则历史：读取审计 `changes`，阈值 `from`/`to` 前后值正确，未出现口令/密钥字段。

回归：gateway `pytest`、web `npm run test` / `npm run build`、flutter `analyze` / `test`、
E2E 全量通过；既有默认阈值告警、SLA、批量指令断言未弱化。

## 已知边界

- 标签只支持「字符串值」，没有独立标签实体与重命名操作；改名需先加新标签、改规则、
  再移除旧标签（见 `docs/operations.md` 16.5）。
- 规则范围不提供跨维度交集（分组且标签）；需要用设备 ID 或拆分规则表达。
- 规则缓存仍为单实例 write-through；多实例部署需每个实例刷新（与 v1.34.0 一致）。
