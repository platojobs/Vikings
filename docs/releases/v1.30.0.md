# v1.30.0 · 报表与数据导出（CSV）

> 发布日期：2026-11-05
> 定位：运维做周报、对账、给客户交月报，不再需要自己写 SQL 或截图。

## 版本定位

- **服务端导出，不是前端拼 CSV**：新增 `/api/exports/records` 与 `/api/exports/alerts`，
  直接流式生成 CSV；浏览器只发一次请求，不翻页拉全量。
- **复用既有筛选语义**：设备历史沿用 `deviceId / start / end`（毫秒或 ISO8601、闭区间），
  告警沿用 `level / status`（级别仍只有 v1.21.0 收窄后的 `warning / critical`），
  两者都支持按 `Device.group_name` 分组过滤；告警列表同步补 `start / end`，
  保证「列表看到的范围」与「导出的范围」来自同一段 SQL 条件。
- **内存不随数据量增长**：`StreamingResponse` + keyset 分页（记录按 `(ts,id)`、
  告警按 `(created_at,id)`），每批 2000 行写入缓冲区后立即发送并清空。
- **上限语义明确**：单次上限 `EXPORT_MAX_ROWS`（默认 200,000），先 count 再流式，
  超限直接 **422** 并提示实际行数与上限。不做静默截断：对账少几行比失败更难发现。
- **CSV 可直接双击**：UTF-8 + BOM、CRLF、中文表头、UTC 时间注明 `(UTC)`、
  逗号/引号/换行转义、前导零保留（`="001"`）、防公式注入。
- **权限收紧并留痕**：仅 operator/admin 可导出，viewer 403；导出结束写审计，
  只记录筛选、行数、耗时、文件名，**不记录任何导出内容**。

## 端点与参数

| 方法 | 路径 | Query |
| --- | --- | --- |
| GET | `/api/exports/records` | `deviceId`、`group`、`start`、`end` |
| GET | `/api/exports/alerts` | `deviceId`、`group`、`level`(warning/critical)、`status`(open/acked)、`start`、`end` |

响应头：`Content-Type: text/csv; charset=utf-8`；
`Content-Disposition: attachment; filename="<kind>_<start>_<end>.csv"`（无范围时
`<kind>_all_<今天>.csv`）；`Cache-Control: no-store`。完整契约见
`docs/contracts.md` 3.10.7。

## 真实大数据实测（真实 PostgreSQL + 真实 uvicorn）

执行：`gateway/.venv/bin/python scripts/verify_exports.py`（独立验证库
`iot_export_verify`，造 200,000 条 `sensor_record` + 200,001 条 `device_alert`）。

| 指标 | 结果 |
| --- | --- |
| 网关启动后基线 RSS | 111.3 MB |
| 导出 20,000 行（对照） | 1.77 MB / 0.27 s / RSS 峰值 **117.6 MB** |
| 导出 200,000 行 | **18.84 MB / 5.59 s / RSS 峰值 119.5 MB**（较基线 +8.2 MB） |
| 文件检测 | `file` → `CSV text`；`file -I` → `text/csv; charset=utf-8`；首 3 字节 `ef bb bf` |
| Python `csv` 回读 | **200,000 行 × 11 列**，表头中文完整 |
| 特殊设备名 | `华东, "1号" 设备\n(新)` 在 120,000 行中原样回读（逗号/引号/换行） |
| 前导零 | 设备 ID `001` 写出 `="001"`，回读一致 |
| UTC | `2026-10-01 00:00:01`（表头 `上报时间(UTC)`） |
| 告警筛选导出 | 17,280 行 × 15 列 / 2.07 MB / 文件名 `alerts_2026-10-01_2026-10-02.csv` |
| 告警内容转义 | 2,468 行含换行并可回读；`-20°C...` 自动加 `'` 前缀防公式 |
| 超限 | 未筛选告警（200,001 行）→ **HTTP 422** `导出 200001 行超过上限 200000 行，请缩小时间范围，或按设备 / 分组分批导出` |
| 权限矩阵 | viewer **403** / operator **200** / admin **200**（未登录 401） |

**对比分页 API 全量拉取同一 200,000 行**：100 次请求 / 5.43 s / **28.67 MB JSON**，
网关 RSS 峰值 123.4 MB，客户端 `tracemalloc` 峰值 **7.27 MB**（仅解析 JSON，未渲染）。
在本机同一 PostgreSQL 上两者墙钟时间接近（导出 5.59 s vs 分页 5.43 s），
但分页需要 100 次往返、传输体积多 52%、客户端还要自行聚合与拼表；
真实前端逐页渲染/去重成本远高于此。导出仍是周报/对账的正确入口。

审计真实内容（脱敏）：

```json
{"filters":{"deviceId":null,"group":null,"level":"warning","status":"open",
 "start":"2026-10-01T00:00:00+00:00","end":"2026-10-02T00:00:00+00:00","maxRows":200000},
 "rows":17280,"duration_ms":179,"filename":"alerts_2026-10-01_2026-10-02.csv"}
```

审计 detail 仅含上述四个键；导出内容（告警文案等）不落审计。

## 界面

- 历史查询：新增「导出 CSV」，使用当前设备与时间范围；导出中显示已接收体积并禁用重复点击。
- 告警中心：新增时间范围筛选（与列表查询共用），新增「导出 CSV」；
  导出使用当前设备/级别/状态/时间范围，viewer 按钮禁用并给出可读提示。
- 失败提示直接展示后端中文 `message`（如 422 超限），不显示「未知错误」。
- 文件名由服务端 `Content-Disposition` 决定，前端只负责保存；无时间范围时如实标记 `all`。

## CI 边界

保持 7 作业：`gateway` / `postgres` / `web` / `device_app` / `device_app_release` /
`images` / `e2e`。大数据验证**不进常规 CI**：需要独立 PostgreSQL、写入 40 万行，
耗时与磁盘相关，放进每个 PR 会让 7 个作业为环境抖动背锅；它放在
`scripts/verify_exports.py`，发布前手动执行并把输出写入本文件。
`test_exports.py` 只用 SQLite、单次几毫秒，归属 `gateway` 作业；`postgres` 作业继续
覆盖真实数据库的迁移往返与核心用例。

## 兼容与升级

- 无数据库迁移：只新增查询端点、配置项与审计动作字符串。
- `GET /api/alerts` 新增可选 `start/end`，不传时行为完全不变。
- 移动端仅 `pubspec.yaml` 同步 `1.30.0+29`，无代码变更。
- 新增环境变量 `EXPORT_MAX_ROWS`（默认 200000），不配置即使用默认值。

## 明确未覆盖 / 偏差

- **浏览器侧仍会完整缓冲文件**：服务端内存是平的，但下载 Blob 需要浏览器持有整份文件
  （20 万行约 19 MB）。这是浏览器下载模型的限制；超大导出建议按月拆批。
- **Web 暂未暴露分组筛选**：导出 API 已支持 `group`，历史页仍按单设备导出，
  告警页未加分组下拉；按分组拆批可通过 API 或后续版本补 UI。
- 导出为单次 HTTP 请求：客户端断开后服务端会尽快停止流式查询，但仍可能已读取若干批次；
  审计照常记录已生成行数与耗时。
- `file` 的多行输出只显示 `CSV text`，编码与 BOM 由 `file -I` 与原始字节 `ef bb bf` 双重确认。
