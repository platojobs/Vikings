# v1.29.0 · 告警通知通道（Webhook + SMTP）

> 发布日期：2026-11-05
> 定位：补齐「告警只有 App 内角标，值班的人不在 App 里就收不到」的核心缺口。

## 版本定位

- **真实投递，不是「函数被调用」**：Webhook 走真实 HTTP POST，SMTP 走真实
  `aiosmtplib` 连接；本版用本地 HTTP 接收器 + 本地 SMTP 桩完整验证了收发两端。
- **两个通道、一套规则**：Webhook（可配 URL / HMAC 签名 / 超时）与 SMTP
  （host / port / 账号 / 收件人 / STARTTLS），共享级别、分组、白/黑名单与静默规则。
- **配置存库、热读取**：`notification_config` 单行配置，每次告警派发直接读库；
  Web 保存后下一条告警立即生效，**无需重启网关**。
- **通知是旁路**：异步派发 + 指数退避重试；发送失败不影响告警入库、不影响
  `device/system/alert` 发布、不阻塞 MQTT 消费。
- **可排障、可审计、不泄密**：投递记录分 `sent / failed / suppressed`；
  失败原因只保留状态码/异常类型；URL、密钥、SMTP 口令不回显、不进日志、不进审计。

## 能力与真实边界

### 通道

| 项 | Webhook | SMTP |
| --- | --- | --- |
| 必填 | URL | host / port / from / to |
| 认证 | 可选 HMAC-SHA256（`X-Vikings-Signature: sha256=...`） | 可选账号口令 + STARTTLS |
| 超时 | 1–60 秒 | 1–60 秒 |
| 重试 | 1–10 次，指数退避 | 1–10 次，指数退避 |
| 测试通知 | `event=notification.test` + `X-Vikings-Test: 1` | 主题加 `[测试]` |

Payload 由 `event / sentAt / alert / device` 组成；alert 保留
`alertId / deviceId / level / metric / value / threshold / message` 等字段，
接收端无需再回查网关即可路由。

### 规则（组合过滤）

- `levels`：`warning` / `critical`，默认仅 `critical`；
- `groups`：设备分组白名单，空 = 全部；
- `device_allow` / `device_deny`：设备 ID 白名单/黑名单，**deny 优先**；
- 三个维度是**且**关系，任一不满足即不投递（级别不匹配不写投递记录）。

### 静默窗口（mute）

- 同一设备同一指标在 `mute_minutes`（默认 10 分钟）内只通知一次；
  后续命中写 `channel=mute / status=suppressed`，不重复发送。
- **告警仍然入库、仍然实时推送、在 App 告警中心仍然可见**；静默只抑制通知。
- 与既有 `ALERT_SUPPRESS_SECONDS`（入库层默认 5 分钟去重）是两层：
  前者决定「App 里看到几条告警」，后者决定「其中几条会发通知」。

### 可靠性

- 每次投递独立留痕：通道、状态、尝试次数、脱敏错误；
- 接收端 500：按 `backoff × 2^(attempt-1)` 重试到上限，最终 `failed` 可见；
- 通知异常全部在旁路任务内吞掉，告警主链路不受影响；
- 测试通知与真实告警共用同一投递函数，避免「测试能过、线上不走代码」。

### 安全

- GET 配置只返回 `webhook_url_configured / webhook_secret_configured / smtp_password_configured`；
- PATCH 审计 `notify.config_update` 只记录**变更字段名**；
- 投递 `error` 不含 URL、host、账号、口令；
- `httpx/httpcore` 与 `aiosqlite/sqlalchemy.engine` 的 INFO/DEBUG 日志统一压到 WARNING，
  防止 URL 与 SQL 参数把密钥写进日志；
- 配置写入仅 admin，测试通知允许 operator（便于值班自检），viewer 403。

## 界面

- Web「系统设置」新增「告警通知通道」卡：总开关、级别、分组、白/黑名单、静默窗口、
  Webhook 与 SMTP 分栏；敏感输入留空 = 保持原值，另有「清空敏感配置」。
- 「发送测试通知」真实调用通道并逐通道显示成功/失败与尝试次数；
- 「最近投递记录」表格可按状态过滤，展示时间、设备、指标、通道、状态、尝试、错误原因。

移动端本轮**不做通知配置页**：App 继续展示全部告警与角标；静默窗口只影响
Webhook/SMTP 发送，不影响 App 内可见性。

### 1. 真实投递脚本（本地 HTTP 接收器 + 本地 SMTP 桩）

  - Webhook payload 样例（截取）：
    `{"event":"alert","sentAt":"2026-11-05T03:26:36.265047+00:00",`
    `"alert":{"alertId":"alt-dev-critical-voltage","deviceId":"dev-critical",`
    `"level":"critical","metric":"voltage","value":2.9,"threshold":3.2,...},`
    `"device":{"deviceId":"dev-critical","groupName":"默认分组","status":"online"}}`

    错误密钥得到
    `sha256=5e5c818277350aa7f43fc5d4a6f49ec9b65d01d65e04707a477335b70fc4fd1b`，校验不通过。
  - SMTP 收到的邮件头：
    `Subject: [CRITICAL] 设备 dev-critical voltage 越过阈值`；
    `From: alerts@vikings.local`；`To: oncall@vikings.local`。
- warning 告警 + 规则仅 critical → `dispatch 结果: []`，两通道均未新增。
- 配置热更新：Webhook URL 从接收器 1 切到接收器 2，**未重启网关**，
  `接收器1 增量=0`、接收器 2 收到 1 条。

  `DeviceAlert total=3`，告警在 REST/DB 仍全部可见。
- 接收端 500 → `webhook` 记录 `failed / attempts=3 / error=HTTP 500`，

- 脱敏：日志与审计中均搜不到 Webhook 密钥、SMTP 口令与完整 URL；
  审计 detail 样例 `{"fields": ["mute_minutes", "webhook_url"]}`。

## 实现要点

- 新增模型：`notification_config`（id=1）、`notification_delivery`；迁移 `0006_notifications`。
- `notify_service.dispatch_alert` 自建会话、自吞异常，由 `handlers.py` 用
  `asyncio.create_task` 派发；告警入库与 MQTT 发布在创建任务之前完成。
- `notify_service.send_test_notification` 复用请求会话，真实调用同一投递函数并留痕。
- Webhook 使用 `httpx` 发送原始 JSON bytes（保证 HMAC 可复算）；SMTP 使用
  `aiosmtplib`，支持 STARTTLS 与认证。
- 静默判定查询同 `device_id + metric` 最近一条 `sent/failed` 记录，窗口内写
  `suppressed`；不修改 `device_alert`。

## 兼容与升级

- 新增迁移 `0006_notifications`，只建两张新表与索引，不动既有表/数据。
- 既有 `ALERT_WEBHOOK_URL` 不再参与投递；状态页仍保留旧字段展示，
  实际通知以「系统设置 → 告警通知通道」为准。
- 默认无配置：通知关闭，行为与 v1.28.0 一致；启用后才开始外连。
- 移动端仅 `pubspec.yaml` 同步 `1.29.0+28`，无代码变更。

## 明确未覆盖

- SMTP 真实投递验证使用本地桩的明文 + AUTH PLAIN 路径；生产 STARTTLS 由
  `aiosmtplib` 标准实现承担，未在本轮对真实公网邮件服务器做联调。
- 投递重试在进程内完成，网关重启会丢失「尚未完成」的剩余重试；已成功/失败记录保留。
- 通知配置为单行全局配置，暂不支持按设备分组配置不同接收人；
  多副本部署时各副本读同一数据库，配置一致，但投递各自执行（可能重复发送）。
- 移动端通知配置页、通知历史页不在本轮范围。
