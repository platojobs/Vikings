# 真机验收清单（v1.23.0）

发布前在真实设备 + 真实网络环境下逐项执行。每项都写清「怎么操作」与「看到什么算通过」；
任一项不通过则阻断发布，并把证据（时间、设备 ID、命令输出、日志片段）附到发布记录。

- 适用版本：`v1.23.0`（设备端 `1.23.0+22`）
- 环境：生产反代地址（HTTPS）、真实 Broker、真实 PostgreSQL；移动端安装 release 包（非 debug）
- 账号：`operator` 与 `viewer` 各一个；准备一个可物理断电/断网的设备
- 证据目录建议：`docs/acceptance-runs/<日期>/`（截图、命令输出、日志摘录）

## 0. 准备

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 0.1 | `curl -s https://<域名>/api/health` | HTTP 200，返回 `status=ok` |
| 0.2 | `curl -s https://<域名>/api/health/ready` | HTTP 200，`components.database.ok=true`、`components.mqtt.connected=true` |
| 0.3 | Web 登录 operator / viewer | 两端均可登录；viewer 看不到管理入口 |
| 0.4 | 设备上电，确认固件/设备端版本 | 设备端显示 `1.23.0`，与 `GET /api/devices/{id}` 的 `firmware_version` 一致 |

## 1. 设备接入

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 1.1 | 设备使用 `deviceId` + 签发凭证连接 1883（或 9001 看板） | Broker 日志出现该 clientId 的 CONNECT，无 ACL deny |
| 1.2 | 设备发布 `device/{id}/status` = online | 5s 内 `GET /api/devices/{id}` 的 `status=online`，`last_seen` 更新 |
| 1.3 | 设备上报一帧 `sensor/report` | Web/移动端看板 3s 内出现该设备与最新数值；`GET /api/records/latest` 包含该设备 |
| 1.4 | 断开设备电源 6 分钟（超过离线阈值 300s） | 设备变为 `offline`；Web/移动端状态同步；审计无异常报错 |
| 1.5 | 重新上电 | 设备自动恢复 `online` 并继续上报，无需人工删除/重建设备 |

## 2. 凭证签发与轮换

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 2.1 | `POST /api/devices/{id}/mqtt-credential`（operator） | 返回新 `username/password/version`；响应 `reloaded=true` |
| 2.2 | 立即用新凭证连接，旧凭证再尝试连接 | 新凭证成功；旧凭证被拒绝（CONNACK 5/Not authorized） |
| 2.3 | 重启 Broker 后再次用新凭证连接 | 仍可连接（凭证已持久化到 password_file） |
| 2.4 | 非 admin 账号调用签发接口 | 403；Web 不展示该按钮 |
| 2.5 | 检查网关与 Broker 日志 | 不出现明文口令；审计记录包含设备 ID、版本与操作人 |

## 3. 指令下发

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 3.1 | Web 设备详情下发 `config`（如上报间隔 15s） | 设备 3s 内收到并生效；`GET /commands` 状态依次 received/progress→success |
| 3.2 | 设备回执 `failed`（可用测试设备模拟） | 指令终态 `failed`，原因文案可见；任务计数 failed+1 |
| 3.3 | 指令下达后立刻让设备离线，等待超过 `COMMAND_TIMEOUT_SECONDS` | 指令被后台巡检置 `failed`，message 含「设备超时未回执」；不会永久 issued |
| 3.4 | 用设备 A 的 Topic 回执设备 B 的 cmdId | 网关忽略并记 warning；设备 B 指令状态不变 |
| 3.5 | 对同一指令重复/乱序回执（先 success 再 progress） | 终态保持 success，进度不回退到 progress |

## 4. OTA 升级

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 4.1 | Web OTA 页选择设备，创建任务（目标版本 `1.1.0`） | 任务 `total=1`，设备状态先 issued/received |
| 4.2 | 观察设备下载/校验/写入过程 | REST/WS 进度单调递增（如 10→30→55→80→100），最终 success |
| 4.3 | 任务完成后刷新任务详情与设备详情 | `success=1 failed=0`、设备 `progress=100`、`firmware_version=1.1.0` |
| 4.4 | 查审计 `GET /api/audit-logs?action=ota.create` | 存在该 taskId 记录，含操作人、目标版本、设备数 |
| 4.5 | 设备侧制造失败（校验失败或断网至超时） | 任务终态 `failed`，原因可见；**固件版本不被误标为目标版本** |
| 4.6 | 对不存在的设备创建 OTA 任务（REST） | HTTP 400 且提示缺失设备；不产生永远凑不齐 total 的僵尸任务 |
| 4.7 | OTA 进行到约 30% 时重启网关（`docker restart`） | 重启后进度仍为 30%，不回退；设备补发 success 后任务转 success；停机期间的回执/上报明确丢弃 |

## 5. 告警确认

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 5.1 | 触发一条 critical 告警（电压低于阈值） | 3s 内出现在 Web 与移动端告警列表/中心 |
| 5.2 | 单条确认并填写备注「已到现场检查」 | 状态变已确认；`acked_by=当前账号`、`acked_at`、`ack_note` 可见 |
| 5.3 | Web 多选 3 条（含 1 条已被别人确认、1 条已删除）批量确认并带备注 | 摘要分别显示 `acked / already_acked / not_found`，数量与实际一致 |
| 5.4 | 移动端重复 5.3 | 结果语义与 Web 完全一致；刷新后状态一致 |
| 5.5 | viewer 账号打开告警页 | 多选/确认按钮禁用并说明原因；直接调 `bulk-ack` 返回 403 |
| 5.6 | 查审计 | 记录操作人、确认条数、备注摘要；日志不含备注全文中的敏感信息 |

## 6. 断网 / 弱网

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 6.1 | 手机开启飞行模式 30s 后关闭 | 移动端自动重连，列表自动刷新；不出现重复数据或空白页 |
| 6.2 | 用网络限速工具把带宽降到 200kbps、丢包 20% | 页面首屏 < 5s 出现骨架/加载态；请求失败有重试入口；不无限转圈 |
| 6.3 | 弱网下执行告警确认 | 成功或用明确失败提示；不得显示「成功」但服务端未落库 |
| 6.4 | 设备断开 Broker 30s 后恢复（Broker 不停） | 设备状态 offline→online；恢复后新指令仍可下发与回执 |
| 6.5 | 停止 Broker 1 分钟再启动 | Web/移动端从实时降级为轮询且提示；Broker 恢复后自动回到实时；网关 `/health` 全程 200 |

## 7. 后台省电行为

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 7.1 | 移动端切后台 10 分钟再回前台 | 回前台 3s 内刷新数据；WebSocket 自动恢复；不重复弹旧告警 |
| 7.2 | 开启系统省电模式，锁屏 30 分钟 | 不崩溃、不 ANR；回到前台可继续操作 |
| 7.3 | 关闭系统对该应用的后台限制后重复 7.1 | 行为一致；无持续高耗电（系统电量统计无异常高占用） |
| 7.4 | 设备端模拟器/真机连续运行 24h | 无内存持续增长导致重启；上报间隔无系统性漂移 |

## 8. 异常提示文案

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 8.1 | 输入错误登录口令 | 提示「账号或口令错误」，不暴露账号是否存在 |
| 8.2 | 连续登录失败触发 429 | 显示剩余等待时间；不在倒计时结束前重复发请求 |
| 8.3 | 断网提交指令 | 提示「网络不可用/提交失败，请重试」，不显示成功 |
| 8.4 | 无权限访问管理页（viewer） | 展示无权限说明并可返回；不出现空白/白屏 |
| 8.5 | 服务端 5xx | 提示可读错误与请求 ID（`X-Request-Id`），便于对号排查 |
| 8.6 | OTA 失败/超时 | 展示失败原因（设备失败、超时秒数），提供重新创建任务的入口 |
